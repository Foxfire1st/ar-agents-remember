# .git-blame-ignore-revs

## Governing Overview

[overview.md](overview.md)

## Purpose

The list of formatting-only revisions `git blame` should skip. It exists because
260731-EFA-L2 added `ruff format --check` as an enforcing gate step, and formatting had
never been gated before, so the change had to be preceded by one whole-tree reformat
commit that would otherwise become the blame answer for a large part of the repository.

## Code Commentary

### Logic

A comment header stating the admission rule, followed by dated entries newest-last. Each
entry is a full 40-character SHA preceded by the command that produced it.

The single entry today:

```text
# 2026-07-31 -- `python -m ruff format .` across the whole tree.
00e83791d4d21bf56fd5b3cc0af194bc5e28112a
```

That commit reformatted **216 of 607 tracked Python files** (391 were already formatted)
with no hand edits, and is the mechanical prerequisite for requirement L2-R4.

### Conventions

The header states the admission rule explicitly: a commit belongs here when it changed no
behaviour, was produced by a formatter or another mechanical rewrite, touched many files,
and every line it moved still has a meaningful author in the commit before it.

It also states the honesty rule: **an entry is only honest if a reader can re-run the
recorded command and get the same tree.** That is why each entry carries its command.

Enabling it is one command per clone:

```bash
git config blame.ignoreRevsFile .git-blame-ignore-revs
```

GitHub and GitLab read the file for their blame views with no configuration.
`git blame --ignore-revs-file .git-blame-ignore-revs` works ad hoc.

### Invariants And Boundaries

- Behaviour-changing commits never belong here. The file is a navigation aid, not a way
  to hide a commit.
- It is **not** enforcement machinery: nothing in the gate reads it. Its counterpart in
  the gate is the `ruff-format` step, which is what stops the drift from recurring.
- Without this file the reformat commit would push real authorship one `git blame` hop
  further away for every file it touched, and each subsequent mechanical rewrite would
  add another hop.

## Purpose

The kept closeout procedure: contextual authority, durable gates, paired worktree publication, granted branch-direct landing, same-generation recovery and explicit boundaries.

## Code Commentary

The transfer retains the operating closeout procedure. The opening comment identifies only the retired Explicit Legacy Operation Repair as naming an unexposed operation. The old MCP table's named-leaf direct_landing verify/create forms remain as one unchanged block under Granted Branch-Direct Landing; it is false to describe the entire old table as unexposed tooling.

Ordinary closeout uses the paired code/memory worktree and commits code before prepared memory content. It consumes the Worker's targeted checks and the Curator's complete quality handoff; the transaction itself does not run quality, tests or independent review. Standalone/final work needs explicit developer authority; subordinate series leaves follow their recorded delegated authority.

Granted branch-direct landing addresses a leaf delivered without its own worktree enclosure. A pre-work direct-execution grant and named-leaf/candidate-tree binding distinguish it from ordinary closeout; the procedure shows both existing-commit verification and new-commit creation forms. Finalization rechecks abandoned-but-landed contradictions for atomic and organizational masters. Retirement/whole-sprint archiving have their own named document operations.

The procedure preserves immutable Git inputs, per-leg publication journals and no automatic push. Recovery distinguishes code-proven/memory-missing from memory-proven/ledger-missing states of the same generation. It does not create a second code commit for an already proven code leg. The sibling worktree-operations workflow owns start, attach, status, sync, integration, finalization and cleanup under their own authority stops.

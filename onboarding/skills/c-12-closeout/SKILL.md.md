## Code Commentary

Every later converted landing is judged again: leaf integration judges the closeout pair, recorded leaf landing judges the supplied landed memory against the recorded memory base, with the recorded closeout code when the landed code equals or descends from it, otherwise the landed code, and master final/checkpoint/recorded routes run validator, net staleness, chain and authentic-history checks. Direct landing may explicitly name its history owner with `leaf_id`. The incoming instruction's intent-less public-recovery warning applies to legacy generations without either compatible task intent or the admitted canonical-leaf input; the real executor's kept closing receipt remains separate. Current `leafTaskDocumentRef`-bound doorless direct generations retain their advertised recovery controls, so absent task intent alone is not a public-recovery refusal. Public recovery continues the accepted generation through the existing executor and settles its kept closing receipt in the same call when completion succeeds. Ordinary missing-intent closeout treatment and earlier door-bearing direct records remain separate.

- Public direct recover continues the admitted generation and settles its retained closing receipt on completion. [10]

The skill owns closeout sequencing while the worktree manager owns start, integration, finalization, and cleanup: ordinary closeout preview and apply run against the enclosure contract with explicit nonblank commit messages per enabled leg, and operation control resumes or cancels the advertised generation only. On converted memory both tools ask the mandatory invariant gate about the exact candidate pair, and the memory commit records exactly the tree the gate judged.

On unconverted memory, both closeout tools refuse `legacy-format` before
claiming approval or committing: preview returns `knowledge-gate-refused`, not
`would-closeout`, and apply refuses the same way. This is independent of converted
memory elsewhere. Convert first through `c-13-install-and-onboard` and
`docs/guides/first-conversion.md`, then close out the converted leaf under the
validator/invariant gate; the conversion itself counts as no change. A failed
crossing plan leaves the line unchanged; a retained conflict or validator refusal
after merge start uses the existing `continue`/`cancel` recovery.

Authority is contextual but never assumed: developer-gated closeout previews first and sends preview facts plus the commit ask to its parent through role_message; parentless work ends with that ask in chat. Apply waits for approval and is never in the relay turn; subordinate accepted-series work retains recorded delegated authority. No product component raises or decides a gate now. An earlier stored closeout-approval gate still refuses admission until the explicit developer-commanded removed-stores route resolves it; this is neither a second lifecycle nor permission to silently discard old authority.

Memory cannot be disabled for a task: every closeout runs under the invariant gate, and a contract on disk that carries the removed mode is abandoned and started again rather than closed out. Closeout order commits code then memory-content with code attribution trailers, refreshes the consumer ledger cache without staging it, and refuses before mutation on moved refs, conflicts, blank messages, or unreconciled pairs. Branch-direct landing stays a policy-gated counterpart for a canonical granted leaf without its own enclosure, never a direct-checkout path; legacy operation repair is explicit and bounded; worker and curator failures route back to their owners rather than becoming gates.

## Purpose

Agent doctrine for closing out approved Agents Remember edits as code and memory Git transactions. Closeout is worktree-only with code-then-memory commit order, always authority-gated, and never an automatic push; it runs no quality checks, test suites, or independent review itself, because curation is already complete before it starts and travels with the handoff as the prerequisite.

## Code Commentary

The skill owns closeout sequencing while the worktree manager owns start, integration, finalization, and cleanup: preview and apply run against the enclosure contract with explicit nonblank commit messages per enabled leg, and operation control resumes or cancels the advertised generation only. On converted memory both tools ask the mandatory invariant gate about the exact candidate pair, and the memory commit records exactly the tree the gate judged.

Authority is contextual but never assumed: standalone and final work relays the preview and asks the developer through the orchestrator hand-off protocol, ending the turn after the notification; subordinate work inside an accepted series applies under delegated authority with the source recorded. The closeout-approval block is evidence of an explicitly raised human gate, never a second lifecycle, and no durable gate is created as an incident workaround.

Memory cannot be disabled for a task: every closeout runs under the invariant gate, and a contract on disk that carries the removed mode is abandoned and started again rather than closed out. Closeout order commits code then memory-content with code attribution trailers, refreshes the consumer ledger cache without staging it, and refuses before mutation on moved refs, conflicts, blank messages, or unreconciled pairs. Branch-direct landing stays a policy-gated counterpart for leafless delivery, never a direct-checkout path; legacy operation repair is explicit and bounded; worker and curator failures route back to their owners rather than becoming gates.

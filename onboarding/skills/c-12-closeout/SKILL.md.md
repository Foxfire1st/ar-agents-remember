## Purpose

Agent doctrine for closing out approved Agents Remember edits as code and memory Git transactions. Ordinary closeout is worktree-only with code-then-memory commit order, always authority-gated, and never an automatic push; it runs no quality checks, test suites, or independent review itself, because curation is already complete before it starts and travels with the handoff as the prerequisite.

## Code Commentary

Every later converted landing is judged again: leaf integration judges the closeout pair, recorded leaf landing judges the supplied landed memory against the recorded memory base, with the recorded closeout code when the landed code equals or descends from it, otherwise the landed code, and master final/checkpoint/recorded routes run validator, net staleness, chain and authentic-history checks. Direct landing may explicitly name its history owner with `leaf_id`. The incoming instruction's intent-less public-recovery warning applies to legacy generations without either compatible task intent or the admitted canonical-leaf input; the real executor's kept closing receipt remains separate. Current `leafTaskDocumentRef`-bound direct generations retain their advertised recovery controls, so absent task intent alone is not a public-recovery refusal.

The skill owns closeout sequencing while the worktree manager owns start, integration, finalization, and cleanup: ordinary closeout preview and apply run against the enclosure contract with explicit nonblank commit messages per enabled leg, and operation control resumes or cancels the advertised generation only. On converted memory both tools ask the mandatory invariant gate about the exact candidate pair, and the memory commit records exactly the tree the gate judged.

Authority is contextual but never assumed: standalone and final work relays the preview and asks the developer through the orchestrator hand-off protocol, ending the turn after the plain preview/commit ask and STOP, not after invoking a removed lifecycle notification tool; subordinate work inside an accepted series applies under delegated authority with the source recorded. The closeout-approval block is evidence of an explicitly raised human gate, never a second lifecycle, and no durable gate is created as an incident workaround.

Memory cannot be disabled for a task: every closeout runs under the invariant gate, and a contract on disk that carries the removed mode is abandoned and started again rather than closed out. Closeout order commits code then memory-content with code attribution trailers, refreshes the consumer ledger cache without staging it, and refuses before mutation on moved refs, conflicts, blank messages, or unreconciled pairs. Branch-direct landing stays a policy-gated counterpart for a canonical granted leaf without its own enclosure, never a direct-checkout path; legacy operation repair is explicit and bounded; worker and curator failures route back to their owners rather than becoming gates.

## Granted direct verify and create

Bind the canonical leaf reference and current readable grant. With code_commit, direct_landing verifies existing code; without it, create preview/apply require code_commit_message and memory_commit_message, and apply needs the previewed code candidate_tree. Direct create judges the exact code/memory pair with its mandatory census before the one code commit, then pairs memory in the accepted generation. A recoverable cut resumes that same generation; real ambiguity keeps its developer-decision path. Ordinary closeout consumes existing curation evidence and does not become a new test/review campaign. Git publication remains the owning Manager transaction, never the Curator.

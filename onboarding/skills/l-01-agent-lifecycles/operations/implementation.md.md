## Message/file transport

This canonical role/operation requires messages to be short wake-ups naming requested work or a handover and its files. Report, verdict, list and evidence contents travel through file-only `body` or existing-file `attach`, not pasted into message text. Within a shared task, files stay with its record and a leaf workspace exposes the message-folder link. Text uses the effective settings limit without a pinned number. The canonical source and generated copies share this contract; transport does not change their existing write/start powers, peer destinations or independent acceptance authority.

## Purpose

The Worker's build contract: implement the leaf's primary requirement in the code worktree, leave one truthful report and one uncommitted candidate, freeze it, and hand it directly to the Reviewer — then the hand-off list directly to the Curator after code PASS.

## Code Commentary

One report at the canonical task path records change, files, evidence, exact checks and open limitations. The freeze handover also carries the leaf Requirement Attempt Journal records appended before review handoff; it is factual, never a review brief. Sealed findings return as a new freeze to the same Reviewer. The candidate stays uncommitted; the seat starts no role, repairs no transaction authority, and stages nothing. A hand-over counts only on a reply or report naming its exact object; busy refusals are recorded, retried, and reported once more. The operation carries no Messages section: that passage has one home in `roles/worker.md`, whose capsule compiles it for the Worker. Before each freeze the Worker passes the coding guidelines' handover checks on a clean copy of the final candidate and names each check, the copy's tree and its result; a carried check run stays valid only while the files it exercises are byte-identical; measurement tooling goes to the Manager as a simple handover that is not a review freeze; and a small defect costing about an hour, a second repair round or a second freeze is reported to the Manager with a proposal while the rest continues.

## Current composition and authoring contract

This stage still gives Worker the selected primary requirement, paired code edit root and read-only memory context. It requires a truthful canonical report and exact factual freeze/journal handover directly to Reviewer, with producer list to Curator after code PASS.

The `ar:roles all` marker exposes the body to every admitted role of this operation, which remains Worker alone. Candidate-uncommitted, no role start, no self-acceptance, no memory/transaction writes, exact-object handover evidence, retry and split sync ownership hold, together with conditional sync, direct repair and per-finding freeze obligations.

## Clean sync and visible direct repairs

When the master line moves, Worker runs its supported leaf sync. If no path changed on both sides, Worker reruns focused tests once and tells Manager; Manager uses its closeout preview. No new freeze goes to Reviewer and no round begins. An overlapping path or a failing focused test instead needs the exact repair and one look by the same Reviewer. Native memory conflicts still go to Curator for content and Manager for capture, verification and staging before Worker continues the supported transaction.

Worker repairs a sealed finding directly in its own task files. No plan, account, census, approval or Manager go-ahead precedes that repair. The supported whole commit check and the freeze remain required. The freeze gives each repaired finding its own ID, cause, files and line ranges, discriminating failing-before/passing-after test and result; unrelated changes are listed separately. After code PASS, the direct Curator handoff carries those same entries and changed paths.

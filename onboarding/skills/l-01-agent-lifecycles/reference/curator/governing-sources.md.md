## Purpose

The Curator's rules for reading governing documentation before explaining an assigned contract, and for preserving governing decisions and rejected alternatives.

## Code Commentary

Before explaining an assigned contract, the Curator inspects the relevant documentation declared in the resolved `system/sources.md`, including its Domain Documentation entries, and opens the actual documents; a registry entry is a pointer, not evidence, and any required source that could not be read is named. This selects evidence for the assigned work, not a repository-wide documentation pass. On converted memory, each developer ruling and requirement-packet choice that still constrains code becomes a decision record with the alternatives it weighed, while task-only decisions stay in the task; decision-record fields and rejected-option input are defined in the hand-off ingestion template. The Curator role links each of the two sections at its own action, and the entity-catalog section of `card-formats-and-citations.md` links the documentation section before choosing domain evidence.

## Evidence

- Governing documentation comes from the resolved sources registry and is opened, not taken from the registry entry. [1]
- Decisions that still constrain code become decision records; task-only decisions stay in the task. [2]
- The Curator role links the decision section before authoring a decision record. [3]

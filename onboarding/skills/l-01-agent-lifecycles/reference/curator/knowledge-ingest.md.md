## Purpose

The Curator's rules for preparing and ingesting authored knowledge: target explanations, the plan-to-write sequence and the semantic scope the Curator supplies.

## Code Commentary

The reconciliation's requirement-shaped items are authored knowledge, not onboarding prose. The file links the hand-off list's producer entry contract, the Curator's authored keys and the writer's input sections at their actions. Every target needs its own authored `rationale`; `role` is optional, and the writer neither generates a rationale nor admits an unexplained target. The writer writes records under `knowledge/`, `realizes` and `proves` sidecar entries and the leaf's history file; command-line runs that decide or write first bind the serving build, and the ingest result is read through the publication-report detail. The worklist command persists the leaf's worklist beside its contract, and the writer reads that worklist with the contract's code and memory roots. Ingest plans with `commit: false` until the plan returns without refusals, then writes once with `commit: true`. An entry of an existing invariant whose meaning is unchanged quotes the record's current statement exactly.

## Evidence

- Authored knowledge follows the hand-off templates, and each target carries its own rationale. [1]
- The writer owns sidecar JSON and the history file, after the serving-build binding. [2]
- Plan without commit until free of refusals, then write once; unchanged statements are quoted exactly. [3]

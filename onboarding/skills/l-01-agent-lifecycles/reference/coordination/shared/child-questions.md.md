## Purpose

Owns the relay of child questions and developer answers across the existing parent route, for Architects, Orchestrators and Managers.

## Code Commentary

A decision within the receiver's authority is answered and labelled as that receiver's own answer. A question beyond that authority passes unchanged to the parent with the originating role, task and agent identifier and a separate recommendation; a seat without a parent asks the developer in its own chat. The developer's words and their attribution pass unchanged on the way down, and no parent presents its own answer as the developer's.

Role-instruction rulings name the exact packet or role file and heading and land through the owning task's review and curation; measurement text-change rulings name the superseded packet sentence and renew budgets, and new wording reaches a seat only through a new start or completed reload. Permission notices stay on the existing parent route, the parent route applies only where a parent exists, and payload and full-store receipt handling belong to `message-handover.md`.

## Evidence

- The relay distinguishes the receiver's answer from a developer ruling and preserves originating identity. [1]
- Instruction changes keep their owning task route, and new wording reaches a seat only through a new start or completed reload. [2]
- Permission notices keep the existing parent route, and message handling points to `message-handover.md`. [3]

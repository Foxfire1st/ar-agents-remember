## Purpose

The one home of the loop doctrine: owner, builder and reviewer at the leaf and master levels, with opt-in review on the agreed seam, explicit baseline/fix-verification modes, settings-governed rounds, standing criteria catalogs, per-level agent sets, and requirement compilation before task topology.

## Code Commentary

The owner never self-approves, the builder never lands, the reviewer never decides — verdicts are evidence. Review runs only when requested, with an explicit mode; independence needs another agent. Review scope follows the agreed seam and explicit mode rather than an invented score; organizational leaf review and atomic integration review keep their distinct scopes, and a changed label or coordinating level creates no new baseline or mandatory review. A governed review follows the settings limit with sealed fix-verification lists; the candidate, source, requirement, model, seat, route or report label never resets the list. The baseline runs the standing `criteria/` catalogs; requirement compilation into stable ID and version packets precedes every task document except the first sprint's launcher-created scope documents (sprint, master and first leaf, carrying only the developer's request and scope), and cold readers must recover change, stability, failure states and proof from the packet alone.

Two routes may add a finding after the list is sealed: a valid code finding from the Curator, and a valid finding from an advisory review the Architect commissioned and forwarded. Each becomes a new sealed finding with its own identifier that reopens the verdict for that point only; earlier sealed findings stay as they are. A repair round for a Curator finding counts under the settings limit, and an extra round for advisory findings is the Architect's grant. One developer request is one task: an owner does not split it alone but proposes a split, with its dependencies, to the developer.

## Canonical Source Ownership

The byte-equal package copy is a distribution carrier, not an independent role, task or permission authority. Whole-file source evidence does not certify inherited statements, execution, grading or the whole card.

- Owner, builder and reviewer never take each other's acts; verdicts are evidence. [1]

- Review is opt-in on an agreed seam and explicit baseline/fix-verification mode. Baseline covers the complete agreed diff; fix verification retains sealed findings, with rounds governed by the settings limit and recorded extra-round authority. [2]

- Requirement compilation into stable ID and version packets precedes task topology. [3]

- Settings-governed rounds, recorded extra-round approval and preserved stage/ownership boundaries. [4]

- Organizational leaf review and atomic integration review keep distinct scopes; a changed label or coordinating level creates no new baseline, and no listed change resets the sealed findings. [5]

- The authored source owns this contract; the distribution copy is not a separate authority. [6]

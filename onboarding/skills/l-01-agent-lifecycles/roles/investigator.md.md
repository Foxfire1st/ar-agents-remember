## Purpose

The canonical role contract for one scoped investigation.

## Code Commentary

The concern may be a provider/system problem, source route, stalled check, procedure, comparison or command cost. Parent-started concern arrives in the actual parent’s first role_message; missing concern or scope is asked of that parent. A parentless launch uses the developer request without inventing repository, task or parent identity. Allowed selections are Projects, sprint or sprint/master; a leaf is named inside the concern and never selected as this role’s start altitude.

Reading needed source, memory, tasks, reports, logs and provider state and checking in scratch or the repository tooling sandbox leads to the supplied report path. Observations and hypotheses remain distinct with confidence. Code, enclosure, memory and task mutations stay forbidden even after a separate order; needed changes are named for Worker or Curator. Provider/system remediation requires the report first and an explicit authorized developer or actual-parent order, and an alert forbidding starts still forbids provider start/restart. The report is returned in the own chat and its path sent to the actual starter. Harness helpers hold no AR seat; a finished turn proves no semantic acceptance.

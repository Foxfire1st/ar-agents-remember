## Message/file transport and return addressing

Messages are short wake-ups naming work and files; report/verdict/evidence content travels in file-only `body` or existing-file `attach`, not pasted text. Within a shared task the files stay in its record and a leaf workspace exposes the folder link. Wake text uses the settings limit without a pinned number. Ordinary report-written notices and final report-path returns use the supplied parent role/task address, including an instructed reporting-recipient change. Developer-needed questions remain addressed to the actual parent/instructed-recipient ID. These are distinct message purposes, not an ID exception to the return rule. Fixed launch-parent identity and existing role/peer/write/acceptance boundaries remain preserved.

## Code Commentary

The concern may be a provider/system problem, source route, stalled check, procedure, comparison or command cost. Parent-started concern arrives in the actual parent’s first role_message; missing concern or scope is asked of that parent. A parentless launch uses the developer request without inventing repository, task or parent identity. Allowed selections are Projects, sprint or sprint/master; a leaf is named inside the concern and never selected as this role’s start altitude.

Reading needed source, memory, tasks, reports, logs and provider state and checking in scratch or the repository tooling sandbox leads to the supplied report path. Observations and hypotheses remain distinct with confidence. Code, enclosure, memory and task mutations stay forbidden even after a separate order; needed changes are named for Worker or Curator. Provider/system remediation requires the report first and an explicit authorized developer or actual-parent order, and an alert forbidding starts still forbids provider start/restart. The report is sent with `role_message` on `agents-remember-task` to the supplied parent role/task return address, which may resolve a replacement occupant; without a parent the developer reads it in the own chat. The actual starter remains concern, developer-question and remediation-order provenance; an ordinary report return is not addressed from an earlier message's agent ID. Harness helpers hold no AR seat; a finished turn proves no semantic acceptance.

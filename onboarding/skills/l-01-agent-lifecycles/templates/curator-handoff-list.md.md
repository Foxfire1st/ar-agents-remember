# skills/l-01-agent-lifecycles/templates/curator-handoff-list.md

## Message/file transport

This canonical template requires messages to be short wake-ups naming requested work or a handover and its files. Report, verdict, list and evidence contents travel through file-only `body` or existing-file `attach`, not pasted into message text. Within a shared task, files stay with its record and a leaf workspace exposes the message-folder link. Text uses the effective settings limit without a pinned number. The canonical source and generated copies share this contract; transport does not change their existing write/start powers, peer destinations or independent acceptance authority.

Defines the producer/curator handoff data boundary. Nine producer fields travel unchanged; the curator resolves the outcome and authors semantic scope, family coverage and external-source provenance.

## Code Commentary

### Logic

Producer entries identify one obligation and all its targets together. Target locators are required; evidence locators may be absent. Statements and producer dispositions are preserved rather than paraphrased. Applicability, conditions and exclusions are authored before invariant ingest.

Converted memory declares a family as a `records` item with its own title, guarantee, exact invariant member IDs and code routes. Nothing is inferred from a shared path or anchor. Read the actual stored members/routes and relevant revisions; a restated guarantee uses the governing changed history row with authored effect and full examined base/candidate member union. This file writer publishes no dataset and uses no database membership-revision selector.

### Current converted judgment-row contract

Current onboarding subjects use updated with a counted Markdown/nonmechanical references change, or justified no_impact. The writer binds every covered source to its candidate blob, including absent for deletion; later source changes reopen the answer. Pre-binding rows remain valid only in closed history and answer nothing in open history. Realizes/proves-only changes do not count. The historical L53 rollout's own changed cards used amended rule 1's measured counted-change exception without updated rows or later backfill; that finite rollout is not a current normal-authoring exception, and the historical MIK-R30 paragraph below is not the new normal contract.

A membership:<invariant ID> no_family judgment carries considered families and the current invariant revision; it answers a new or newly unlisted live invariant and refuses for a familied subject. A record judgment concerns a touched existing decision or other facet record: changed with effect, retired with retire, or no_impact, with applicable because and foreign-owner evidence. New records and the writer's own isolated raise status change do not create touched_record. The writer supplies revisions and item identities; the Curator never writes these rows manually. The earlier L53 producer limitation and assignment of the nine inherited Family examination repairs to L54 are historical rollout custody, not a claim that the current master-line Writer lacks these typed rows. Normal curation uses that admitted producer; the finite condition-to-membership transfer changes neither the recorded no-joint-obligation basis nor the invariant's substantive conditions.

Named validator route reasons replace blanket never-refused claims: registry-designated rules report inside the writer but refuse publication/landing; sync merge and carried migration debt have their stated reporting boundaries. Existing/exported admission and carried absent/unrealized family text below are historical provenance, not permanent gate exemptions. Ordinary content drift remains advisory; carried gone-path anchors are the refusing exception.

A `raise` the command cannot publish refuses the whole batch and names the mounted `knowledge_write` with the absolute contract and hand-off paths, the hand-off name and the authorization reference; no route reads `--config`.

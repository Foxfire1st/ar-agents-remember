# skills/l-01-agent-lifecycles/templates/master-handover-packet.md

## Message/file transport

This canonical template requires messages to be short wake-ups naming requested work or a handover and its files. Report, verdict, list and evidence contents travel through file-only `body` or existing-file `attach`, not pasted into message text. Within a shared task, files stay with its record and a leaf workspace exposes the message-folder link. Text uses the effective settings limit without a pinned number. The canonical source and generated copies share this contract; transport does not change their existing write/start powers, peer destinations or independent acceptance authority.

## Purpose

The artifact a manager hands to the orchestrator at master exit: which completion boundary is ready — the final accumulated organizational candidate or one isolated atomic branch — with refs the receiver resolves and revalidates before deciding.

## Code Commentary

Posted after the prepared transaction inputs and complete handoff reports exist, with an independent master-exit verdict only when review was requested. It names execution nature and exact scope, summarizes code and memory ancestry with canonical evidence (immutable trees, ancestry, accepted commit pairs; attribution from trailers, never branch names), and carries known follow-ups. A missing, stale, unresolvable or candidate-mismatched ref blocks; summaries never substitute for evidence.

## Evidence

- The packet names the ready completion boundary with resolvable, revalidatable refs. [1]
- Refs are immutable trees, evidence locations or stable pointers, never branch names. [2]

## Message/file transport

This canonical template requires messages to be short wake-ups naming requested work or a handover and its files. Report, verdict, list and evidence contents travel through file-only `body` or existing-file `attach`, not pasted into message text. Within a shared task, files stay with its record and a leaf workspace exposes the message-folder link. Text uses the effective settings limit without a pinned number. Before sending the packet the Manager reads `reference/message-handover.md#send-a-message-that-names-the-files` for the sender and payload rules. The canonical source and the packaged copy share this contract; transport does not change their existing write/start powers, peer destinations or independent acceptance authority.

## Purpose

The artifact the Manager hands to the named coordination recipient at master exit — the developer when the Manager has no parent: which completion boundary is ready — the final accumulated organizational candidate or one isolated atomic branch — with refs the recipient resolves and validates before deciding, following `core/acceptance.md#keep-relay-and-gate-owner-duties-separate`.

## Code Commentary

Posted after the prepared transaction inputs and complete handoff reports exist, with an independent master-exit verdict only when review was requested. It names execution nature and exact scope, summarizes code and memory ancestry with canonical evidence (immutable trees, ancestry, accepted commit pairs; attribution from trailers, never branch names), and carries known follow-ups. The packet records the candidate-validation result (resolved refs, mismatches or blockers and the recipient's decision); who decides is in the acceptance handoff-artifact table, and summaries never substitute for evidence.

## Evidence

- The Manager hands the master to the named coordination recipient, or the developer without a parent, and the recipient validates the exact candidate. [1]

- Refs are immutable trees, evidence locations or stable pointers, never branch names. [2]

## Canonical Source Ownership

The authored file is the canonical contract; its measured byte-equal package copy is a distribution carrier, not an independent role, task or permission authority.

- The authored source owns this contract; the distribution copy is not a separate authority. [3]

## Purpose

The report layout the Bootstrap seat fills when it writes its one setup report for a repository.

## Code Commentary

The template supplies sections and state fields only; the Bootstrap role (`roles/bootstrap.md#report`) owns the report duty and completion boundary, and the Bootstrap operation owns the evidence standard. The report's first line is its own report path (`<taskReportPath>`). Resolved State records the coordination and memory roots, the user settings path and what initialization did, the harness per role (model and effort left to harness defaults), the spear branch, the memory branch and HEAD, baseline adoption, and onboarding and knowledge-foundation state as read — never as authored here. Decisions Taken, Steps Run, Steps Skipped Or Failed, the named next step (start the Architect, whose foundation work follows `c-14-knowledge-bootstrap`'s "Who Runs It"), stated limitations and a Boundaries checklist (no commit, branch move, worktree, migration or authored onboarding/knowledge) complete it.

## Evidence

- The role owns the report duty and the operation owns the evidence standard; the template supplies sections and fields. [1]
- The report opens with its own path and records onboarding and knowledge-foundation state as read, never as made here. [2]
- The named next step is starting the Architect, and the Boundaries checklist denies commits, branch moves, worktrees, migration and authored onboarding or knowledge. [3]
- The Bootstrap role points to this template before the report is written. [4]

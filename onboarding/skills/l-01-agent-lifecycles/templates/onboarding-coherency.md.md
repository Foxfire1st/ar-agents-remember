## Purpose

The canonical onboarding-coherency template defines the affected-onboarding handoff report a Curator writes and, when review is explicitly requested, evidence for the reviewer's onboarding-versus-code lens. It records affected sidecar, overview, index and entity changes together with complete curation checks. The complete memory-quality result travels with the handoff as a curation prerequisite for closeout and integration; drift suites remain separate developer-requested operations. The packaged runtime file is a distribution twin, not another authoring authority.

## Code Commentary

### Logic

The report inventories changed source sidecars, new files missing onboarding, the complete check set, governing overview changes and handoff readiness. Its fields describe recipient, analysis role or bounded fan-out author label, reviewed change scope and written time; the author label is not a runtime occupant-ID field. The owning curation operation reconciles existing intent, ruled change and implemented reality rather than substituting a list of diagnostics for that comparison.

Changed files need current sidecar bodies in the same pass, not verification-stamp-only refreshes; new files need created sidecars. Route/repository overviews reflect the change set, including moved, added and deleted slices. The inherited substantive-body/no-impact distinction remains useful, but converted onboarding must not be reduced to newest-first Update History or a template's `lastVerifiedCommitHash` example. Record the actual affected-path checks and their statuses rather than inventing metadata or future commit-derived fingerprints.

### Checks And Handoff

The shape records full `memory_quality_check`, conditional `curator_coherence`, c-05 affected-onboarding checks, `git diff --check`, other named checks and requested drift suites. Each carries its scope/command/result and pass, failed, blocked or not-run status as applicable. It also records whether the ledger maps code HEAD, whether governing overviews reflect touched routes/slices, readiness for closeout and whether failed/not-run checks were reported without a full-green claim. These are report fields, not evidence that the checks ran, a ledger is current or closeout is ready.

The complete curation operation is not optional or replaceable by a subset. Its owning operation requires intake and repair-loop full checks, repair or exact-code blocked escalation of every curator-actionable finding, raw quality readiness, and coherence publication/validation when required. This is completed curation evidence and its existing prerequisite, not authority granted by the report to run closeout or integrate. Full code quality, full test suites, certification, review and drift authorization remain distinct from merely filling curation status fields.

### Invariants And Boundaries

The report carries evidence; it neither stamps metadata nor performs closeout. Do not invent future code hashes or advance fingerprints to uncommitted source. Curation reconciles and writes admitted memory, while the transaction owner retains acceptance and publication. Template recipient fields do not dispatch a role or override its assignment.

The current Reviewer source names impact-analysis and onboarding-coherency as durable route reports. Its baseline curation exception states that the Curator always runs complete memory quality; it does not make a reviewer-authored subset equivalent or assign that authoring operation to the Reviewer. The inherited statement that the onboarding lens paired `read_ar_files` with `grepai_search` is an older retrieval account, not the current Reviewer's tool prescription.

Older orchestrator/shared-operation notes preserve owning-seat boundaries and analytical organization, not a continuing no-native-sub-agents rule. Current router doctrine permits harness helpers within the assignment, gives them no AR seat or independent-review authority and retains exactly one Curator writer. An explicitly requested independent review remains separate from the author's helpers.

### Documentation Scope

The inherited card recorded no template-local TODO and required no sibling-repository evidence for this report shape. The report's formatting and check placeholders do not certify whole-repository coherence, provider availability, executed verification or acceptance.

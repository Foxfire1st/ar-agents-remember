## Purpose

The authored retrieval router chooses the missing-context question before selecting the cheapest discovery substrate. Its operative route uses indexes, named governing knowledge and native file reads to confirm source contracts; retained semantic/relationship catalogs and synthetic examples are not callable provider authority.

## Commentary

### Contract choice and retired-provider tension

Semantics labels an unknown route/location, Relationship labels missing connections around a known anchor, and Intent labels missing contracts or behavioral truth. The current bullets mark the first two retired — no semantic-query and no relationship-query tool — and send the reader to the route index, native search over the code repo and bounded reads. The triage rule starts at Intent, and no catalog here stands in for a retired substrate. The sibling catalog files this account once linked are not in the candidate; the synthetic shapes it shows belong to the inherited account.

### Naming is not reading

read_ar_files accepts up to twenty string paths and names existence, governing card locations, computed counts/states and action-needed record headings, with call-local nearest-first overview locations. It returns no source, card or overview text; removed refresh and object-form paths refuse argument-removed. Native reads of the named files are the research norm both before and after the build decision, not merely an editing precondition. Research-call accounting remains an instruction-level evidence obligation, not evidence that any calls happened here.

### Bounded confirmation and index meaning

Unknown routes start with overview.index.json; prose overviews are conditional on the index being insufficient. Present-by-index selects source plus deterministic sidecar; absent-by-index skips sidecar probing and reads source first. Without an index, only the candidate source’s deterministic sidecar is probed. A capped, filename-narrowed anchor search addresses one unresolved question. Confirmation stops once the subsystem boundary, immediate cause, user consequence and next fix direction are established. coveredFiles means availability, never a prohibition on reading source or proof of a contract.

### Recorded intent belongs to the selected memory tree

knowledge_read names records by text ID, kind, state and file/heading/line, and the caller opens those files. Authored cards/sidecars and knowledge records feed a rebuildable derived index; there is no database publication destination. The writer is named on this route: `agents-remember knowledge-ingest`, or the mounted `knowledge_write`, writes under a task's leaf contract, including the repository foundation work the user-started Architect organises through `c-14-knowledge-bootstrap`; a read of the tree sees those files. Taskless reads use canonical memory, leaf reads use that contract’s memory worktree, with no fallback. Legacy-format, registration_absent and selector_absent name their actual absence/refusal instead of borrowing another tree’s truth.

### Family completeness and continuation custody

source_context selects a path’s own invariants, containing-family headers and members, then ancestor/directory chain-family rows; familyRevisionId without sourcePath expands a chain family. Only knowledge_read carries the described page walk. Its shared token threshold, counts, deferred seeds, header references, oversized rows and queue refusal preserve bounded completeness without returning record text. Continue with the returned memoryTree.memoryRoot, continuationView and opaque token; do not substitute a derived-index path, repository ID or changed ordering/code-tree selection. Binding mismatch restarts from the seed; unreadable continuation names an invalid token/view.

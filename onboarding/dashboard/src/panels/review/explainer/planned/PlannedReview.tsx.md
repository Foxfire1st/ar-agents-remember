## Purpose

The page a leaf shows before any work exists: what the task is meant to produce, its packets and scope paths, the prepared context and its reference files, with only deterministic sorts.

## Code Commentary

- The top line is the product's own and the intended notice travels with the page; neither is taken from the payload's own wording.
- Effects draw twice from one ordered list: a tree of subject and effect rows, and a reading list whose second line is the current statement, the hand-off label or a measured absence.
- Tree rows answer Enter and space as well as a press, and selecting a subject marks both the tree row and its reading row.
- The sort bar draws only the sorts the product offers, so a payload cannot add a control.
- A resolved scope path becomes a link at the code tip and reports its address upward; an unresolved path stays plain text.
- Packet bodies are drawn as inert text, and the component fetches nothing and mounts no frame or host channel.

- The page draws the product's top line, the intended notice, the opened address and the four parts, holding its own sort and selection [1]
- Effects are drawn as a tree and as a reading list from one ordered set, with an empty case stated [2]

- A resolved scope path links to the code tip; an unresolved one is captioned as text [4]
- The prepared context shows its body or the word absent [5]
- Reference files are listed by their task-relative path, including nested ones, or an empty case is stated [6]

## Governing Overview

[review route overview](overview.md)

## Purpose

Project delivered outline, member and leaf-wide code facts into primary badges, grouping, populations and fallback semantic ordering without classifying a new fact.

## Code Commentary

Member facts are joined by supplied identity. A returned undescribed member is unknown. Family triage reports distinct member populations, unknown totals, partial/scoped state and independently authored guarantee status; breakdownText keeps those member counts separate from intent counts. Ordering retains semantic siblings and distinct revision rows, while mergeChangeKinds folds delivered facts over roster continuation.

`outlineGroups` builds admitted family/member and unlisted-invariant rows, with plain unbadged catalogue groups when no outline is admitted. A supplied code map, including null, replaces walked implementation facts; undefined retains them. `memberBadge` preserves real or unknown intent first, then established implementation, joined/left membership, unknown implementation and the original badge. Numeric badge weights and supplementary recorded-meaning labels are separate projections. Member meaning comes from that exact family occurrence or the invariant's own entry, not its family's effect.

Member labels prefer the invariant's outline ID, then its family-outline ID or catalogue label, then a walked display label and finally the supplied identity; the invariant's summary is appended to its title. Every non-authored ReviewSort uses the semantic weight fallback in these helpers; the page's changeSetOrder owner applies its deterministic page sort to the model. outlineCounts and firstOutlineChange remain pure utility projections and do not select the opening subject.

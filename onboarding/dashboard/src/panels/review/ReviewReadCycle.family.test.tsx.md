# dashboard/src/panels/review/ReviewReadCycle.family.test.tsx

## Governing Overview

[Owning route overview](overview.md)

## Purpose

Bounded family continuation controls preserve accumulated claims and selected reading state without replacing a coherent answer with rejected content.

## Code Commentary

### Logic

- Raw captured page-size-4 bodies advance before and after rosters independently. Replays retain exact member and claim populations; primary knowledge and judgment equal their response values while the complete inventory stays the first owner value.
- Explicit corruptions of cursor, code/snapshot identity, subject, repository, family revision, staleness, immutable content and page refusal fail admission and retain the coherent answer. An unadvertised cursor is also rejected; a whole-review refusal still hides the retained payload.
- The mounted rejection matrix waits for every member row to receive its independently read card locations, then checks the specific walk failure code among other read failures. Selected wording, judgment, tree rows, inventory and the published retry continuation remain intact.
- Family details qualify content-only, fully loaded and unavailable claim scope. Refresh, changed subject/history and late superseded continuation controls prevent old accumulation from answering a new question.
- The final mounted journey selects the captured member in its family by subject identity, retains both revision IDs in Technical details, keeps wording, judgment, sibling count and filter focus across continuations, and exposes later claim paths as recorded addresses in member details. It no longer opens a card Full file or chooses an inline code layout.
- A separate ChangeSetViewer helper projects the same captured inventory into synthetic changeset responses to check count and order; it makes no native HTTP or range-admission claim.

### Invariants And Boundaries

Successful review bodies are retained capture inputs; deliberately corrupted copies are negative probes. Historical full-tree bytes isolate chrome and do not qualify the current producer. Fetch/catalogue controls and synthetic ChangeSetViewer replies were not executed here or certified against an installed browser.

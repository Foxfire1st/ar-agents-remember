## Purpose

The R71 role-choice cases: what a user's settings, a repository and the host each decide, and what a selection may not supply for itself.

## Code Commentary

`write_user_settings` changes only the tested family in the user's own file, because the host lives in the authority file. The cases pin host fields winning while each source stays recorded, the host's advertised default for an omitted mode and the launcher mode's precedence over other sources. These cases check harness and model scope for lower choices. Unoffered feature choices can refuse. Unoffered or long opaque mode IDs reach the host. Role-start tools have no mode field. The launcher carries `modeId`, and a permission-bearing feature override still refuses. A repository authority refusal covers both families, while parsing retains the service-tier spellings and the live catalog rejects aliases that resolve to different Paseo IDs; a profile binds by exact name first and reports why one is unavailable. Plain-text overwrite blocks a raw digest and loads no file. Report collection survives removal without following a legacy alias and a failed collection preserves the source and the link target; a handover keeps its assignment and local paths when the baseline is replaced; the collection budget and non-leaf retirement preserve durable reports. Unknown mode offers preserve the named choice or its absence. Known offers without a default yield an absent mode with the host-default source on the choice record. The tests also check unchanged metadata reuse for two evidence sizes and refusal details naming the exact settings and host profile sources. An observed mode and feature mismatch is warned publicly. Each role grant excludes a second configured AR server, completed cleanup collects before the same role folder is removed, the public reader carries no caller path or mutating operation, layer binding keeps one harness's auto apart from another's, per-level origins bind at the authored layer with their provider controls, collection cache churn reaches a bounded fixed point and retires, and a host custom provider needs no AR declaration.

## Invariants And Boundaries

The role-tool request supplies no permission mode. The launcher supplies a `modeId` for the host, and the cases retain refusals for permission-bearing feature overrides. Sources are recorded per level rather than collapsed, and a refusal names the file it came from.

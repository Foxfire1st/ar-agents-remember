## Purpose

Audience projection, frozen step-detail delivery, protected instructions and explicit memory-lane rollout.

## Code Commentary

Combines synthetic common/selected/excluded audience and separate-detail digest controls with real-corpus per-role/operation selection. Independent expected paragraphs and pinned operation bytes protect common/recipient delivery and closeout. Real launch composition writes exact read-only request-local detail artifacts, records paths/steps and replaces placeholders. Curator detail titles/numbers, first-review/reuse timing, nested instructions, writer authority, external backing, execution-support output, own-step completion and three-repair stop text have direct assertions. Reviewer/Curator instructions select the independent recorded memory lane and explicitly retain underway-review/no-backfill rollout.

## Evidence Boundaries

- Source assertions cover the actual delivered corpus and manifest-declared detail population, with content/recipient oracles and mutation controls rather than just current marker-derived ownership.
- The serving-build boundary is required inline for all three Curator stages and excluded by recipient expectations elsewhere.
- Actual harness file reading at the step is not measured; source naming and materialization do not force model compliance.
- Pinned Bootstrap D301 candidate wording is not an unchanged-base or semantic-equivalence proof; the file explicitly distinguishes that exception.
- No new closeout meaning, independent pilot verdict, native launch or migration/backfill is authorized.

This card describes assertion/support/document source, not a test invocation, independent verdict or publication.

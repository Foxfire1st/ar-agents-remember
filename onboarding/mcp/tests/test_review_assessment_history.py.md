## Purpose

Pins unreadable after-tree owner history as unavailable, never false absence, while keeping complete native
failure diagnostics and bounded fixture detail. The historical test name remains, but the retired external
curator-artifact channel, its monkeypatched reader and its literal short wording are not the current interface.

## Code Commentary

### Current regression and real owner boundary

`_unreadable_histories` builds a hermetic review world, writes malformed JSON into actual owner attempt-history
paths, resolves the candidate, then reads `KnowledgeIndex.history_rows_of`. It asserts an incomplete index and
the complete ordered tuple of failed paths. It calls the staying `review_judgment` with the invariant identity
seed and asserts `unavailable` with no judgment rows. Failure paths remain in the native answer's index problems;
they are not a restored external-channel `unreadable` field or evidence of an absent judgment.

The single test body checks two populations. The many-file count is computed from `PROSE_MAX_LENGTH` and the
fixture path width, rather than fixed at the former 100 artifacts. Its full path list exceeds the prose bound;
the pane detail must fit, name the count/first three and remaining population, and omit the last path. A separate
ten-file world verifies the CURRENT exact detail: first three paths, `and 7 more`, and the sentence that history
not read cannot be reported as absent. The old ten-artifact full-error wording is intentionally not retained.

The real `owner_rows` routes an incomplete native answer to `incomplete_detail`; the latter formats a three-path
sample and remaining count. `review_judgment._answer` returns unavailable on that problem before it can produce
`none`. These are the specific fixture and owner boundaries inspected here, not a universal bound for every
arbitrary input path, nor a new Curator execution or independent MEMORY grade.

### Conventions and limits

This is an `evidence_unit` fixture using actual temporary repository/index composition rather than a stubbed
legacy-channel exception. It does not prove normal assessment capture, cleanup/restart, external artifact
retention or exact-parent recovery. Repair08 I4/R6 accepted a clarified regression-property migration; it did
not transfer the old channel's name, payload, path or literal wording to a new owner. Earlier CODE occasions
remain historical and separate.

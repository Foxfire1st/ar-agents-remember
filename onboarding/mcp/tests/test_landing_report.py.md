## Governing Overview

[Test overview](overview.md)

## Purpose

Protects the landing-report contract across pure measurement, Git and working-tree acquisition, converted-quality composition, bounded answers and shipped role text. Tests distinguish report-only observations from invariant gate or closeout refusals.

## Code Commentary

The measure cases assert exact removed/added counts, under-threshold silence, the deleted-source exemption, overview cuts and code-named rename handling. Added-file cases cover the three excluded roots, byte totals, linked-worktree administration, live and dangling symlinks without following targets. Repeated-line controls bound hash work at two input sizes rather than inferring scalability from elapsed time.

Leaf-base cases bind actual memory/code pairs through the application port and show that cuts and additions remain reported after a mid-leaf commit; advancing the admitted base excludes older changes. Adapter and fallback cases keep contract-bound and bare diagnostic runs distinct. Both populations remain report-only while existing validator refusals and actionable counts retain their contracts.

The real-owner cases call `evaluate_leaf_gate` on a paired scratch contract/exact trees and `run_memory_quality_phase` with the real memory-quality adapter. They demonstrate the specified gate/quality-phase boundary, not a published live closeout transaction, certificate or integration. Other helper/checklist examples remain useful unit controls and are not substituted for those real-owner witnesses.

The answer case supplies 200 cut rows and asserts whole counts, a bounded slim first-row list and a token ceiling. The role-source case checks all three Curator sentences and both Reviewer sentences in the source mirrors it discovers. It also compiles canonical Curator/curation and Reviewer/review capsules: the compiled Curator checks all three sentences, but the compiled Reviewer checks only the removed-text phrase. It does not separately compile every harness or assert the added-file sentence in the compiled Reviewer. Reading these assertions is not a fresh pytest run or CODE/MEMORY acceptance.

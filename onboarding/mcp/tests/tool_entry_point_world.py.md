## Purpose

The one world the tool entry-point tests drive.

## Code Commentary

It builds the fixture world, calls registered tools through it and closes its sessions so the sweep and progression tests share one owner. A returned call is judged from two objects: the whole result, read back from the file the delivered answer names in `log` and validated under the tool's registered model, and the delivered answer in its own shape — none of the four envelope fields, and no key that neither the whole result at the same place nor the shaping's framework keys account for. Refusal actionability is read from the delivered answer. One tool's deadline is recorded on that tool and the sweep goes on, so every tool is judged.

## Evidence

- The whole result is read back from the file the answer names, and a missing or unreadable file is an unvalidatable finding, never a fallback. [2]
- A returned call validates the whole result under its model and judges the delivered answer as delivered. [3]
- One shared classifier serves the sweep and the controls. [4]
- A passed phase limit names the tool and the phase, outside the product-raiser classifier. [5]

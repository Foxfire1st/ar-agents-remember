## Code Commentary

The tests drive the source_context, invariant and family views over a converted tree — the three
names are the closed ordered set, and a fourth view is refused before it touches a tree. The view
vocabulary, the closed rule registry and the ordering pass are pure functions of their inputs. The
mounted family is three operations over a memory tree: no registered tool takes a database path,
and `knowledge_change` and `knowledge_project` left the registered set with the canonical
database. The §6 cases drive the registered `knowledge_*` handlers through a real FastMCP server
over a converted memory tree, so the mounted surface executes rather than merely appearing in the
roster.

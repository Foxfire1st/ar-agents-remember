## Purpose

Declare real task_doc authoring witnesses and separate pure ordinary-master Order/projection assertions on disposable task worlds.

## Code Commentary

The world writes real JSON/Markdown through the task persistence owner and invokes the actual application task_doc_tool. Cases name exact invalid IDs across create/replace/set_field, candidate cycles, reserved prose homes and original-entry grandfathering. Gone references survive unrelated writes; an explicitly supplied dependency list rejects removed/abandoned rows while an unreadable still-listed child is not that refusal.

Pure constructed documents separately assert state-aware waves, stored SCC/cycle display (including RF01 Completed-member retention), fileless gone dependencies, child-document stage authority and absent Order for all-empty dependency fields. Native field-write cases assert refreshed master Markdown and corpus heads without persisted waves or changes to the master JSON bytes. Projection cases also assert gone/cycle display.

RF01 adds five source witnesses on the same real task_doc fixture. Omitted-replacement refresh starts with A waiting on B, removes waitsFor from A’s full replacement, then asserts A’s dependency slot is None, the parent Markdown loses Order, the corpus master graph is None, and the captured parent JSON bytes are unchanged. The no-op master dry-run asserts rendered Markdown exactly equals disk, diff is empty, wouldLose is False and the captured files’ bytes are unchanged. The dependency dry-run changes A’s prerequisite from B to C, checks the nested masterSync rendered row uses C and not B, compares captured files before apply, then applies the edit and compares parent Markdown with the preview.

The fixed-prose remedy test crosses no legacy sections versus seeded legacy Objective/Local notes sections, sets all five fixed fields through task_doc, and asserts their text appears in Objective/Non-goals/Requirements/Design/Acceptance order. It compares the persisted sections array with its seeded value and, for the legacy fixture, places fixed Acceptance before the retained Objective and Local notes. It asserts preservation, not deduplication or migration.

The legacy-cycle test seeds reciprocal A/B dependencies through write_task_doc for (inProgress, planning), (Completed, planning), and (Completed, Completed) row states. It asserts exact cycle_ids (A, B), flags for both, one shared wave, neither in ready_ids, cycle flags in the projected master graph, the expected Completed count, and the full Legacy cycle members banner whenever the pair is not all Completed. It compares pre-captured files’ bytes after the pure derivation/projection reads. It does not assert an absent banner for the all-Completed pair or exact wave values in this added case; those details must not be invented from its name. No test here was executed for this reconciliation.

No general all-affected-files no-write promise follows: several older refusals compare only target JSON, and the all-writer ID matrix does not compare unchanged bytes. The new preview/legacy-cycle cases compare bytes for files captured beforehand, not an after-read directory census that would detect every possible newly created artifact. All-empty model cases are not migration runs. These schema-bearing writer fixtures do not themselves decide schema-less named-body parity; the separate body-lookup module declares that admission matrix. Source assertions, retained Worker execution evidence and independent review remain separate; this reconciliation runs none and grants no acceptance.

A cross-folder prerequisite keeps nested/b.json rather than collapsing to the caller folder. Its own Completed stage yields a landed frontier despite a stale planning parent row. Body/corpus dependency lists and bodyRevision agree. Projected dependency links carry reference and gone, not a second status/docPath authority.

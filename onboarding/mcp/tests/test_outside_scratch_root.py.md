# mcp/tests/test_outside_scratch_root.py

## Governing Overview

[overview](overview.md)

## Purpose

This module exercises MIK-R207's outside-scratch allocation, publication records, refusal, recreation and removal boundaries. It checks one private root per enclosure generation, its recorded identity and handover field, ordinary-root deletion guarded by retained completion proof, and the separate guarded cleanup of interrupted staging directories. Each evidence claim below states the observation made by its named case.

## Code Commentary

### Fixture custody

Outside-scratch allocations in this pytest process use a redirected parent: the session-autouse `_isolated_outside_scratch_parent` in `conftest.py` repoints `outside_scratch.OUTSIDE_SCRATCH_PARENT` from `/var/tmp/agents-remember` to this pytest process's own `outside-scratch` directory inside `/tmp/ar-pytest-*`, created `0700`, so those in-process allocations use the isolated parent. That isolated tree is deeper than the product's 22-character parent, so the same fixture raises `outside_scratch.SOCKET_PATH_LIMIT` to 4096; the module's own autouse `_socket_room` repeats that per case, and only `test_a_root_too_long_for_a_sandbox_socket_is_refused` sets the limit back to 108 to measure the rule itself. The module's autouse `_no_root_outlives_the_case` snapshots the parent's roots before each case and afterwards removes only roots that appeared during it and whose marker parses to a record, while the support module's `publish_test_enclosure` registers every root a publication creates for removal at `atexit`. Teardown never sweeps by name: `discard_owned_roots(base, parent)` reads each marker's `coordinationRoot`, resolves it, and removes the root only when that path is the invocation's own temporary base or lies under it, so a parallel worker's base (a different `pytest-NNN`) never matches and its live roots survive, and a second call returns `[]`. The session fixture applies that same ownership test to both the isolated parent and the original product parent, because a test served from a separate process allocates in the real parent without ever loading the fixture, and it restores both globals before removing the isolated parent. The surrounding process environment is neutralised in `conftest.py` rather than here: `HOME`, `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_CACHE_HOME`, `CODEX_HOME` and `TMUX_TMPDIR` point into the same isolated tree, global and system Git config are disabled, and inherited `AR_RUN_*`, `AR_SPAWN_*`, `AR_HOSTED_*`, `*_API_KEY`, `*_ACCESS_TOKEN`, `*_AUTH_TOKEN`, `GITHUB_TOKEN`, `GH_TOKEN`, `SSH_AUTH_SOCK`, `TMUX` and `TMUX_PANE` are popped.

### What the cases pin

- The generation is a digest over the repository, the contract path and the predecessor generation; the root is `ar-` plus its first twelve characters and a successor never reuses its predecessor's root (`test_the_generation_is_derived_and_the_root_stays_short`). After publication returns, the manifest records the expected path, generation and marker digest, the root is a real `0700` directory with a schema-carrying marker, and the published record matches the expected record (`test_publishing_an_enclosure_allocates_its_root_before_its_contract`). The record survives the round trip through contract text, a retry of the same generation reuses it instead of founding a second root, and a contract from before this change records no root, yields no removal entry and no blocker, and publishes no manifest field (`test_a_recorded_root_survives_the_contract_text`, `test_a_pre_change_contract_records_no_root_and_materialises_nothing`, `test_a_pre_change_publication_writes_no_new_manifest_field`).
- The managed parent is validated before any mutation at both ends of the life: a parent that is a symlink, is not `0700`, or belongs to another uid is refused, and allocation and removal both refuse a redirected or foreign parent without allocating or removing anything (`test_the_managed_parent_is_private_and_ours`, `test_allocation_and_removal_refuse_a_redirected_or_foreign_parent`). A recorded root that stands outside the managed parent is somebody else's and is never removed (`test_a_recorded_root_outside_the_managed_parent_is_never_removed`).
- Refusals protect live data instead of repairing it: a symlinked root answers `symlink` and its target survives, an escaped root answers `outside-the-managed-parent`, an unusable parent answers `parent-unusable`, a tree carrying another generation's complete marker is refused and left byte-intact on allocation and on removal, and a root whose sandbox socket path would reach 108 bytes is refused at allocation (`test_a_root_that_is_a_link_or_escapes_the_parent_is_never_removed`, `test_a_conflicting_generation_tree_is_refused_and_left_intact`, `test_removal_refuses_a_tree_of_another_generation`, `test_a_root_too_long_for_a_sandbox_socket_is_refused`).
- A root that ageing removed is recreated empty under its recorded identity with the same marker digest, whether through a direct `ensure_root`, through the contract's recorded field, or through the manifest on a leaf's next use — and the second use answers the same path without copying what was deleted (`test_a_root_that_ageing_removed_is_recreated_with_the_same_digest`, `test_the_next_direct_use_recreates_an_aged_away_root`, `test_the_next_leaf_use_recreates_an_aged_away_root_from_the_manifest`). The handover names the root only when one is recorded and answers an empty field, and an empty manifest lookup, otherwise (`test_the_handover_names_the_outside_root_only_when_one_is_recorded`).
- Removal answers honestly: a dry run reports `would_remove` and deletes nothing, a root another remover took between the check and the delete is `already-absent`, blocker computation accepts absent or removed roots, reports a symlink refusal, and excludes a `would_remove` preview from blockers, and a completed retry removes the root that remains yet blocks on the one it cannot (`test_a_dry_run_reports_the_removal_it_would_make`, `test_a_root_taken_by_another_remover_is_answered_as_already_absent`, `test_an_aged_away_root_is_not_a_blocker_and_a_remaining_one_is`, `test_a_completed_retry_removes_a_root_that_remains_and_blocks_on_one_it_cannot`).
- For ordinary published roots, the sweep removes a proof-ended generation and reports retained roots with a reason: `generation-not-ended`, `marker-missing-or-unreadable`, `marker-names-another-path` or `symlink`, while the offending tree stays (`test_the_reconcile_deletes_only_a_root_it_can_prove_is_finished`, `test_an_active_generation_is_reported_and_kept_by_the_reconcile`). The terminal owner proves the live generation only once its cleanup progression completes, not when the archive is merely published (`test_the_terminal_owner_proves_an_ended_generation_once_its_cleanup_completes`, `test_an_archive_ready_generation_keeps_its_root`), and a successor proves a replaced predecessor only through the completion record retained beside its archive and receipt, not through the vanished worktree group (`test_a_successor_proves_its_predecessor_only_through_its_completion`). An interrupted publication's `.partial-` root is swept, a sandbox's own tree leaves with its enclosure, and the startup hook invokes the patched sweep and its event is observed within the wait bound (`test_an_interrupted_publication_is_swept_rather_than_left_behind`, `test_a_sandbox_use_of_the_root_ends_with_the_enclosure`, `test_the_tool_server_start_sweeps_the_roots`).
- Paging takes every root in name order however the stream yields them, walks a parent larger than one pass in two passes of `MAX_ROOTS`, and with `MAX_ROOTS` set to two each pass reports at most two removals, repeated passes remove all five roots including those behind the first page, and completing the walk clears its cursor (`test_paging_takes_every_root_in_name_order_however_the_stream_yields_them`, `test_a_parent_larger_than_one_pass_is_walked_to_its_end`, `test_a_bounded_pass_reaches_the_roots_behind_the_prefix`).
- The cleanup report keeps a removal that really happened: an already-clean answer carrying the removal at the top level beside empty `directories` is reported as removed rather than as nothing left in place, and the retry's nested-entry shape is reported the same way (`test_an_already_clean_answer_keeps_its_removal_in_the_report`, `test_a_completed_retry_reports_the_root_it_removed`).
- Teardown is ownership-bounded and repeatable: with one root under the invocation's base, one under a sibling worker's base and one under neither, only the owned root is removed, and a second call removes nothing (`test_teardown_removes_only_this_invocations_roots`).

## Boundaries

`startup.start_outside_scratch_reconcile` starts a daemon thread in source. The named final-state publication case does not observe temporal ordering; the startup event case does not distinguish a caller-thread sweep from another thread or measure handshake timing. The bounded-pass case observes reported removals and eventual coverage, not the number of entries inspected.

- A live `pnt_sandbox` launch is not performed; the sandbox tier is present as the tree shape it writes, and its start/stop and process records belong to `test_pnt_sandbox_processes.py`.
- The cleanup and abandon commands' own progression is not re-tested; `test_cleanup_repeated_archive_ready.py`, `test_cleanup_completed_contract_remains.py` and `test_lifecycle_playthrough_end_to_end.py` own those promises.
- The compiled handover text and role routing are not checked beyond the `outsideScratchRoot` field; `test_role_launch_routes.py` and `test_leaf_handover.py` own them.
- The archive, receipt and sync-journal placement rules are driven as builders here, not measured; `test_terminal_enclosure_archive_sync_journal.py` owns them.

## Evidence

- The parent-refusal cases retain an interrupted staging directory and its marker under a wrong-mode or foreign-owned parent, preserve the cursor under a refused parent, and then recover the same staging directory under a valid parent (`test_a_partial_root_is_not_deleted_through_a_refused_parent`, `test_a_refused_parent_leaves_the_reconcile_cursor_untouched`). A linked partial entry is reported as `symlink` while its target survives (`test_a_symlinked_partial_entry_is_reported_and_never_followed`).
- A sweep over one proof-ended generation removes it while the archive-ready and the still-active generations remain, each reported under its own reason instead of being deleted.
- The teardown case leaves a parallel worker's root and a foreign root standing while removing the root it owns, and repeats as a no-op.

# mcp/tests/test_tool_descriptions.py

## Governing Overview

[Python test route](overview.md)

## Purpose

Pins the registered tool-description contract and the reachable longer-explanation file. It checks actual FastMCP advertisements rather than guessing the published arguments from adapter syntax.

## Contract And Boundaries

The description probe registers the product's actual registrar set, collapses whitespace, and requires its names to equal the public roster. Ordinary finalized descriptions meet the 600-character ceiling and end with a recognized pointer. Explicitly interim-owned descriptions keep their recorded transition lengths; the removed dispatch description has no retained special pin. These pins are not an ordinary finalized-tool exception table.

The argument check walks the complete advertised input schema. It checks the current node before descending through properties, model definitions, composition branches, items and additionalProperties, so a model or a container cannot hide an overlong description. The separate pure model control distinguishes the 121-character rejection from the 120-character boundary without a server fixture. A declared check is not evidence that all live published models already pass it.

The pointer recognizer accepts documentation files, named skills and skill URIs. Files and named skills resolve to checkout paths and are checked for existence; a skill URI is recognized but has no local filesystem target in this helper. The shipped reference has a stronger file-specific chain: the moved-detail inventory checks that omitted calling material survives, a packaged-copy test requires byte equality, and a disposable install reads back the installed reference. Its watcher operation is patched; this is not a real-provider or host-ambient-exclusion witness.

## Evidence


- The registered description check compares the actual advertised roster, preserves transition length pins and checks the ordinary ceiling and longer-explanation pointer. [1]

- Published input schemas are inspected recursively, checking each node including model/composition/container descriptions. [2]
- The pure model control rejects 121 characters and accepts the 120-character boundary, separately from the live whole-schema assertion. [3]
- Pointer interpretation distinguishes local documentation/skill paths from the recognized URI spelling without a local filesystem target. [4]

- Moved material, packaged byte equality and disposable installed-reference read-back protect the longer explanation; the install probe patches watcher operations. [5]

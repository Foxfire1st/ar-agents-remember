## Purpose

Protect the completed-direct owner disposition and interrupted-direct public recovery boundary.

## Code Commentary

The public fixtures distinguish owner retire and its idempotent re-answer from stranger refusal and unavailable direct supersede. Predicate mutations check kind, derived fingerprint/key identity, disposition, status and an explicitly expected generation. Omitted persisted counters parse to 1 before normal owner judgment. Stored door-carrying direct records project no controls.

The offer/admission matrix includes integrated contracts, active integration claims and cancelled idle claims. The first-leg-only recovery fixture pins code to its accepted commit while memory HEAD is still its accepted before-state, then exercises the public control through same-generation completion and closing-receipt settlement. A post-memory-publication interruption is a separate recovery scope, not the first-leg witness. Repeated recovery and wrong expected generation refuse.

After owner retire, the converted same-leaf case refuses advanced code with `direct-landing-knowledge-gate-refused`, retaining completed generation 1 and its retired disposition without creating another history attempt. The converted fixture explicitly names another leaf, checks both correctly closed histories and leaves memory clean; it does not reopen the first leaf's closed history. Source assertions are evidence of the contract, not a claim that this Curator executed pytest.

## Purpose and current source account

The suite checks the same-build tool definition and returned binding, a compact launch instruction, bounded regular handover artifacts, exclusive writers and exact retry refusal/reuse. New leaf launches use a real `role-reports` access folder and the canonical artifact path; retry restores a missing folder, refuses altered artifact bytes until deletion, and reuses the saved receipt/message without adding a link. Pre-existing alias receipts retain separate link-restoration and disagreement controls. The two storage generations are not interchangeable. These are dispatch/tool/artifact contracts, not proof that every provider uses the offered server correctly.

## Locator path beside the stored artifact

The hand-over cases now read the written file through `canonicalPath`, which is the artifact beside the report, while the reference's `path` is the request's locator: the path the recovery note and the first message give the agent. The leaf retry that restores a removed report folder brings the same locator back, so the path the agent was given opens the restored bytes; the retry of a saved receipt compares `canonicalPath`, and the conflicting complete hand-over control passes a request id so publication settles a locator before writing. The recovery-note case asserts both the stored assignment beside the report and the reachable locator path, and the receipt keeps the two apart.

## Purpose

These cases protect the read and refusal boundaries for historical closeout and integration journals and their coexistence with direct-landing controls.

## Code Commentary

The compatibility cases exercise retired worker fields and nested preparation commands. A complete closeout record generated by the old models is read from the current store without rewriting its fixture bytes. The cases check replacement guidance at retry, recover and resume and keep the stored generation inspectable. The registered status case compares the control recommendation for an interrupted direct landing before and after adding historical records, with canonical task intent supplied for the stored direct record.

## Relationships

The evidence lifecycle catalog owns the permanent fixture contracts. The registered control cases in `test_lifecycle_operation_public_boundary.py` verify the public result type and exact next-call arguments.

## Purpose

The module holds the per-role freedom and boundary clause tables, the leaf role/operation positive obligation tables and their normalized readers. The wording tests assert these clauses and remove each one to prove the guard fails; the module authors no knowledge itself.

## Code Commentary

The module is part of the leaf's direct hand-over and instruction-guard evidence. It holds no AR seat, starts no role, authors no knowledge and performs no boundary act; its tests run in the ordinary candidate population.

The Worker and Reviewer positive obligations name individual stage starts: at freeze the Worker tells the Manager to start the Reviewer, and on code `PASS` the Reviewer tells the Manager to start the Curator; each peer handover goes directly once the receiving seat exists. These clause tables preserve independent review and one Curator writer. Generated mirrors remain the public generator’s outputs.

## Current audience, delivery and evidence contract

`delivered_step` is now the common route for named-detail wording checks: it binds the selected role/operation through real admission and compilation, checks one exact source reference with a nonempty step and exact bytes, requires exactly one pointer to that detail at the named action (`assert_action_pointer`), materializes launch files and verifies the recorded entry, every emitted detail link's path and fragment, and the stored bytes. `autonomy_clauses(role)` returns that role's entry of `AUTONOMY_CLAUSES`, an explicit table for each of the eight roles in `ROLES` (architect, bootstrap, curator, manager, orchestrator, reviewer, investigator, worker). Each alternative must express the whole named obligation, so deleting any condition cannot leave a weaker alternative passing. `IMPLEMENTATION_CLAUSES`, `REVIEW_CLAUSES` and `CURATION_CLAUSES` hold the leaf operation obligations that `LEAF_CLAUSES` spreads into the role entries. Memory-review wording distinguishes the new recorded memory lane from untouched code state; these strings are not a semantic language gate.

MESSAGE_HANDOVER_SOURCE pins reference/message-handover.md, and MESSAGE_HANDOVER_ACTIONS names for each role the action sentence at which that detail's pointer must stand. REFUSED_WRITE_ACTIONS names the Manager's task retirement and movement action for the refused-write detail, and SERVED_REFUSED_WRITE is that file's served address. The busy-retry alternatives require a pending record, independent work, one resend before turn end and a still-pending state after another full-store refusal. The consuming clause_surface path checks this detail through the actual admitted role and operation; the literal oracle does not establish that a live sender followed it.

# Worktree Lifecycle Implementation Modules

## Governing Overview
[worktrees overview](../overview.md)

## Purpose

`worktrees/modules` implements the operations and focused adapters behind the public worktree-manager facade. Its responsibility is to turn an addressed task contract, explicit approval, exact Git candidates and configured services into start, attach, sync, closeout, landing, cleanup, abandon and finalization results. It also owns lifecycle guidance, CLI argument conversion, onboarding refresh and trace rules, candidate-pair identities, historical code-object release, and the stop-only atomic-master pause.

The route separates observing a lifecycle from authorizing its next mutation. A phase, preview, planned parent, published historical coherence digest or activation observation does not itself authorize implementation, prove a live process, certify a candidate or permit deletion. Reopen belongs to the task-document application route and `worktrees/reopen.py`; start consumes its reopened lifecycle state rather than owning the reopen operation.

Normal delivery is a code/memory transaction. The earlier automatic strict-quality, curator-coherence and independent-review sequence is historical delivery policy, while the explicit certification machinery remains under `quality/`. This does not remove the present converted-memory knowledge gates: closeout still asks the candidate gate before claiming approval, validates and gates the exact converted memory output at publication, and gates recovered memory output. Integration and record landing retain their own converted-memory and cutover predicates.

Start resolves the canonical task identity and branch plan through `startup/`, admits task-derived ancestry and configured repository authority, plans memory/provider work, and materializes only on apply. Manager bootstrap and first-leaf start share the master-series contract owner. Sync is contract-addressed and resumable. Preview skips fetch and delegates observation without publishing activation or journal residue. Apply refreshes upstream evidence, rereads the contract, refuses a changed contract, then delegates to the ordinary or selected atomic-series transaction. The inherited conflict contract retains code/memory resolution worktrees: continue validates the staged resolution, cancel restores only pinned operation-owned heads, and conflicts are not silently aborted.

## Construction And Ownership

checkout_holding_branch selects the actual non-bare, non-detached owner of the named branch so a series code mutation has a concrete intent/proof checkout. It reads repository facts; it is not a grant, code publisher or quality gate.

`start.py` coordinates start/status/attach and provider requests. `startup/start_contract.py` owns durable structural bootstrap; `master_series_admission.py` owns persisted edge comparison and bounded refusal projection; `leaf_ref_start.py`, `start_memory.py`, `start_provider_preflight.py`, `start_plan.py`, `start_result.py` and `series_attach.py` isolate resolution, planning, admission and response construction. Provider setup/teardown execution belongs to `application/provider_runtime.py`, reached through service ports, rather than the deleted local provider modules. The inherited provider lifecycle retains synchronous preflight, background real setup, progress/retry observations and a live-setup retirement guard; dry-run must not launch setup.

`args.py` supplies the frozen cross-layer argument DTO, including nested task selectors and normalized effective closeout input. `cli.py` converts namespaces and prints operation results. The historical explicit leaf-id heal command is a migration invocation, not normalization on ordinary contract reads. Legacy synchronous closeout apply is not an alternate delivery authority.

`git.py` owns Git helpers, candidate capture, staging and tree publication, importing the shared kernel runner rather than defining another runner. New tree publication runs the repository pre-commit check on the exact staged tree before commit-tree and records its Commit-Check-Pass fact; failing or mutating hooks refuse before refs move. Raw Git names/results preserve the runner's byte-decoding contract; raised diagnostics are made transport-safe. Name-only worklists deliberately filter to existing files. Committed worklist paths are the base-to-HEAD tree diff intersected with the last-verified-to-HEAD diff when applicable.

`git_changes.py` is the relocated counted-change owner. Its NUL-delimited status/numstat parsing preserves tabs, newlines, backslashes, destination names, deletions and unknown binary counts, with explicit malformed rename/copy refusal. Its Git read disables automatic index refresh, preserving the real index generation even for identical-byte replacements. The optional changed-path observer runs after status discovery and before numstat, so generation ownership can include the paths' attributes before their counts are read.

Candidate capture uses a unique temporary private index. It copies the actual index with its recorded time, restores HEAD starting entries, clears assume-unchanged/skip-worktree flags on the copy, and stages real working files with explicit derived exclusions. An unusable copy invokes the existing full private capture. The real index and user files stay unchanged, but tree objects may be written into Git. The conversion-rule limit is deliberate: an unchanged file whose cached timestamps still match is not rehashed solely because attributes, filters or autocrlf rules changed; touching the file makes both captures reread it. Private staging is also explicitly supported by `stage_worktree_content`; ordinary staging still uses the real index when no private path is supplied.

The read-local baseline memo now carries an optional capture observer, restored on scope exit even for nested memo use. It notifies only after the fresh post-capture baseline matches the pre-capture observation, allowing the native content-cache owner to observe objects just captured before resolving them. This does not extend memo lifetime beyond its read or turn a changed baseline into reusable proof.

`future_code_candidate.py` binds observed HEAD, configured code base and candidate tree in one frozen strict identity, rejects non-leaf use, checks HEAD across capture, and requires equality of the complete identity on revalidation. Its temporary index now lives in the system temporary directory, not the enclosure. `memory_candidate_pair.py` resolves the external-memory leaf's exact repositories, worktrees, work branches, recorded bases and ancestry after rereading the contract. Completed integration can admit the recorded integrated source heads. The ledger path is a derived consumer address, excluded from the contract digest; typed refusals name bounded field facts and repair actions.

`closeout.py` coordinates admission, approval and contract finalization; `closeout_external.py` owns external-memory refresh/output. Queue closeout recovery supplies typed outcomes and admitted-tip/recovery proof. `integration_recovery.py` retains exact authority-ref convergence and journaled external-memory output proof. Root lifecycle journals own operation generations and durable mutation evidence; historical DAG queue rows are not a second authority. Task truth publishes before derived queue projection invalidation/rebuild.

`landing_record.py` is the shared completed/checkpointed landing-cell writer. `integrate.py` coordinates landing and delegates exact ref preparation/publication to the integration subroute. Non-fast-forward recovery guidance names contract sync, retained code/memory resolution and renewed closeout; replay remains a supported strategy and carryover vehicle, not the preferred repair prompt for stale closeout sources.

`closeout_lineage.py` carries settleable behind-source edges, including ordinary diverged work branches, through the existing sync transaction and then rereads/reproves the contract. Preview reports the duty without mutation. Unavailable lineage escalates to the developer; retained conflict and refused sync return their exact resolution duties. Code resolution calls for targeted verification before retry, memory resolution calls for memory tooling first, and larger repairs return to the responsible worker/curator.

`terminal_agents.py` attempts host archival of recorded leaf agents after admission and before destructive output. It does nothing for preview or series. An unbound service or host/receipt failure is reported and does not refuse an already-admitted retirement; completed cleanup can retry archival. The review-artifact archive hook likewise runs only for an actual/would-be archive, uses the task-root name for the review namespace, and reports unbound/failure rather than raising after a task has moved. Current series finalization receives the archive owner's skip, so hook existence is not evidence that a master was archived.

`pause.py` releases only the addressed series activation and returns control without a next call. It calls the existing release authority, runs no Git locally and owns no landing or closeout. Already-vacant succeeds only after a fresh vacant observation; unreadable or foreign ownership remains refusal. Checkpoint publication is a separate verb. Activation is contract-keyed, not a protected-source-pair lane: inherited IAS policy allows independent graph-less masters concurrently, retains explicit authored predecessor dependencies, reconciles pinned sources before active selection, and never reconstructs missing/malformed authority from a queue or legacy reader. Terminal release may clear only the exact addressed terminal selection.

`code_object_retention.py` reads/releases historical retained-code pins; it creates no new pin or frozen canonical generation. Custody counts only explicitly named durable tips and recorded commits, not a history walk or an arbitrary feature branch. A deeper historical copy therefore remains conservatively retained. Object absence is a distinct observation. Explicit release measures custody, refuses a moved ref, deletes only the recorded expected commit, and converges when the ref is already absent. The caller owns release policy and durable unavailable-history publication.

The integration_gate module owns pre-publication invariant admission for preview and apply: exact leaf-pair rejudgment or master validator/staleness/history plus chain proof. Refused admission persists neither contract nor worklist. Recorded landing judges supplied landed endpoints rather than mutable tips. Git object/ancestry unreadability is a named refusal, never absence.

## Invariants And Boundaries

Removed disabled-memory semantics are not a current code-only delivery option. Closeout, integration, checkpoint, record landing, sync, pause and finalization have explicit opt-out refusals; start distinguishes removed requests and existing-contract observation. A local non-external shortcut in an observational helper does not override those route admissions. Abandon remains the discard route and can reclaim carried memory branches/worktrees regardless of the old contract mode; that exception grants no conversion or normal delivery authority.

Closeout approval is a mutation-attempt claim, not a promise to remain reusable until success. Fresh claiming follows reversible admission and precedes code publication. Durable recovery can resume a recorded claim and proven commits; it must not replay completed irreversible work. A crash or failure after claim does not imply a fresh reusable approval. The inherited rejection of late success-only consumption and timer-reopened claims remains design intent. Integration's local handover consumer is a cross-lifecycle enclosure guard; these inspected functions do not claim that gate. The historical unresolved spend policy needs an enclosure-addressable key and must account for legitimate re-integration. No whole-call-path non-consumption conclusion follows from this local observation.

Converted memory is recognized by `knowledge/layout.json`. Closeout preflight and preview share the candidate verdict; exact memory publication independently validates/gates fresh, unchanged and recovered outputs. Unconverted closeout and record landing refuse through the central legacy-format boundary regardless of converted memory elsewhere. Leaf integration consults the lock only when neither landed memory nor its landing line is converted; series/checkpoint landing asks the landing gate against current code/memory sources. Record landing probes the source line and recorded base first; converted lines require a named readable memory output. A converted leaf pair requires its recorded memory base; landed parents do not replace a missing base. When the judged memory commit equals or descends from the recorded completed-closeout memory commit, history closed in that recorded commit's parents stays frozen while additions remain checked. Outside that ancestry nothing is frozen; unreadable recorded objects/ancestry refuse judgment.

Converted onboarding traces replace Update History/lastVerified metadata. Affected card and nearest-route subjects carry exact candidate code blobs, counted Markdown/reference facts and current eligible row identity. References-only sidecar counting excludes mechanical fields and realizes/proves-only empty-reference changes. Ordinary updated needs a counted change and source binding; no-impact needs current unchanged-contract meaning. Winning rows retain their own file-closed provenance across attempts; sourceless rows answer only from closed files. Input/readability problems stay named, and unnecessary rows retain their subjects. The stored counted-change sentinel is not an ordinary current-row answer. L53's amended rollout rule separately credits its own measured changed card under the old producer, with no changed-card history row or future backfill. Converted refreshers stamp no lastVerified metadata.

Unconverted onboarding retains the body/history rules: changed source cards and nearest governing route bodies need meaningful review plus history, or explicit no-content/no-route-impact attestation. Ancestor overview stamping is report-only. Directly edited overviews since the memory baseline are included even when source drift predates the leaf. Only sanctioned final reference-cell coordinate changes receive the narrow generated citation exception; prose, claim, anchor, path and table-shape changes do not. Candidate-bound no-impact acceptance moves matching unchanged stale classifications to attested while preserving untraced authored content. Missing-card blocking is limited to working paths; transported committed paths remain a nonblocking unonboarded report. Route indexes use resolved storage authority.

Integration and checkpoint must publish the same admitted pair preview proved, with source-tip and contract rechecks at the protected boundary. Checkpoint never grants completion or reclamation. Cleanup requires exact carryover before retiring resources that recovery needs. Abandon without force protects dirty work and unlanded commits; explicit force is its discard exception. The root cache alone is disposable. Terminal agent archival is best effort, whereas terminal archive proof and destructive target capabilities are authority.

Unconverted ordinary memory inputs refuse even in a repository that has never converted. A series preview judges format before publication authority; a converted landed candidate on an unconverted line reaches its own validator instead of being classified from the prior tip. Named unreadable probes remain errors, never format facts. The source line either crosses from a converted source or follows first conversion; ordinary and certified prepared closeout keep their separate gate/preflight and transaction owners. Legacy refusal persists no blocked contract.

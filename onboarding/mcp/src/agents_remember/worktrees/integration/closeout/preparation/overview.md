## Purpose

This package re-proves exact already selected code output, observes Git policy and converts retained private intents to shared kernel bindings. Active code/memory preparation, continuation and pair publication/finalization owners were removed; retained evidence readers do not create a replacement output.

Source route: `mcp/src/agents_remember/worktrees/integration/closeout/preparation`.

## Hot Path Summary

Read `code_view.py` for selected-record currentness, strict existing/private physical reproof and logical-pair-bound view construction. `policy.py` observes actual Git configuration, identity environment and hooks; `private_execution.py` only converts an exact write-enabled intent to a binding. Shared selected intent/output/history readers remain in `preparation_selection.py`; its successor-retention producer and rebound-wrapper helpers were removed.

## How It Is Built

`code_view.py` reopens the selected code intent/output, proves original raw commit bytes and physical state, and rechecks current selection around observation. Existing code uses the logical root; retained created code uses its named private root and sealed reauthorization. Code-domain strictness is unchanged by a file named `memory.md`.

`private_git_binding` preserves exact root/ref/expected-old/parent/tree/message/policy/operation/generation/intent fields and refuses missing write authority, root or message; it executes no Git. `policy.py` retains actual configuration, identity and hook observation.

## Invariants And Boundaries

Retained outputs are re-proven, not recreated. A view, policy observation or binding conversion grants no command launch, memory certification or task-ref publication. Shared strict physical proof and selected-object ownership survive.

Root memory-cache exclusion, existing memory-content projection, attribution and ordinary pair publication remain with their surviving kernel/transaction owners. Removal of the prepared memory-output/reuse/finalizer lane does not retire those shared contracts.

Ordinary closeout and direct landing still publish code plus memory content under their own authority, then refresh the disposable cache; cache availability is not a third output or acceptance identity. Source inspection establishes no aggregate acceptance.

[Canvas route overview](overview.md)

## Purpose

Load one prospective revision in Chromium under the page policy and return a bounded observation for the Python admission owner to check.

## Code Commentary

The loopback server serves only the staged directory under the canvas-page prefix. Document and asset headers mirror the production isolation arrangement; external and absent asset requests are reported. The browser runs with reduced motion and checks for errors, media playing, rendered content and visible painted information. The paint-suppression comparison establishes that information reaches the viewport, not that the explanation is correct.

`observe` inventories `data-evidence` basis references separately from `data-evidence-claim` claim ids and reports empty attributes as unresolved. `watchReferences` keeps both inventories through DOM mutations during the bounded post-load observation; each has its own 401-value ceiling. The Python caller resolves the returned values against its immutable evidence packet. Keeping the inventories apart prevents a claim id being treated as a basis address.

`observeInBrowser` returns these inventories alongside load and reduced-motion facts. Its two-second observation window says nothing about arbitrary later scripts. `answerAndExit` emits one JSON answer and exits; a browser failure returns `unavailable` rather than claiming the page was observed.

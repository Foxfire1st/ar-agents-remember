## Purpose

The explainer’s capability text: its leaf environment and exact recorded or planned binding, admitted read surface, page/part obligations, grades, Update and regeneration, and the conversation and architect-report boundary.

## Code Commentary

- The text names the assignment and the complete output, and states the bounds once.
- It carries a map of the kit — which tool suits which explanation, with search keywords rather than addresses.
- It is shipped twice, as the installed resource and as the checkout copy the budget test reads; the two files are byte-identical.

The text names `instructions/`, `scratch/`, `drafts/` and read-only bound snapshots; permits only the bound server’s reads and guarded authoring tools; and requires the product’s grade tools and publication command rather than direct accepted-record writes. It distinguishes intended planned claims, a moved binding’s refusal, explicit Update and developer-requested stale regeneration, and a report whose developer words the product copies exactly.

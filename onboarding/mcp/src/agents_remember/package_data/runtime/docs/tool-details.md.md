## Purpose

The shipped longer explanations behind `server_info`, `runtime_install`, `role_start_set`,
native `retire_child` and converted-onboarding drift descriptions. The canonical checkout document is
`docs/tool-details.md`; this packaged copy installs under `<coordinationRoot>/docs/`,
making the same relative explanation pointer openable in both layouts. It is
documentation, not another callable interface.

The drift account distinguishes anchor assessment from invariant currentness. A stale
reference anchor refuses closeout/APPLY, integration, direct and recorded landing and the
full quality run as `R198.1-reference-anchor`, and only the drift summary, the writer and
a sync merge report it for repair. A carried anchor at a path the leaf deleted keeps its
`R22.6-carried-stale` route. This replaces the earlier reporting treatment of stale
references for every kind, not only the gone-path one.

## Code Commentary

Long citation previews can start in the background and be polled with the same repository and leaf contract; they never apply repairs. Synchronous writes retain their ordering while other reads and polls can answer. The converted memory check lists Git-tracked and non-ignored untracked sources, reports skipped paths and checks readable cited content independently of onboarding path rules. The canonical and packaged explanations have identical bytes in this candidate; the passed shipped-document tests check that equality and the disposable install location.

The baseline-adoption explanation now distinguishes the actionable-drift gate from paired-tree validation. `accept_drift` can lift only the former; a stale code/test reference still refuses as `R198.1-reference-anchor`, and the first converted baseline is validated before commitment. The option does not make an invalid paired tree adoptable.

The canonical and packaged document carry long explanations for `citation_fix`, `context_packet`, `curator_coherence`, baseline adoption, carryover planning, memory quality, child retirement, role-set start and route-index refresh. Short registration descriptions point here, but callable signatures remain defined by registration, not this document. The citation explanation now replaces source-index snapshot options with unconditional old-format refusal and conversion, while preserving finite card selection, measured admissions, sidecar authoring and full logged detail. The installer-owned documentation-copy route is unchanged.


`server_info` takes no arguments and reports startup-loaded build/configuration, roots, allowed repositories, unused provider and removed-part settings keys, plus optional role binding. `openUserSettings` reports live open file/folder modes with the exact user close/edit commands; the call changes no settings byte or mode and does not enumerate tools. Configuration load failure remains a startup refusal.

`runtime_install` documents preview, optional benchmark fixture copying, retained provider
knobs, and per-call experimental selection. Its `role-capsules` experiment uses request
then environment selection; unknown ids refuse before mutation, and unselected reruns
restore withheld legacy startup targets. The document separates read-only host preview,
absent-host setup information and needed-restart/outside-host remedies.

The server_info explanation no longer advertises harnessSkillRoot. Runtime install manages documentation and applicable AGENTS targets; skills remain package-served MCP resources in both experiment modes, with no installed skill copy. Host maintenance reads paseoRuntime from the active --config MCP authority file per use, writes no authority settings and defers a required restart. These are documentation contracts, not evidence that an installer or host ran.

Provider setup is retired; old enabled keys are unused and only watcher stop remains. A failed installer stop is reported while installation continues; explicit `providers-remove` owns provider deletion. `removedPartStores` reports retained old stores and stored gates once, with `agents-remember removed-stores` as the user-commanded removal route; install deletes none of them. Managed scaffold pruning is not blanket deletion of preserved memory/provider/store data.

`role_start_set` is owning-Manager-only and reconciles the same Worker/Reviewer/Curator set by request ID. Worker opens immediately; Reviewer opens with supplied first work or stays held, and Curator stays held. Native `retire_child` is original-starter-only, requires explicit interruption authority for an active turn, records its reason and is idempotent for an already retired agent. It is not the removed structural retirement plane.

## Code Commentary

### The transitive pin the operator's install resolves

This lockfile (`lockfileVersion` 3) is what `npm ci` installs from once
`install_eve_application` has copied the mirror into `<coordination_root>/runtime/eve-agent`; the
recorded one-line command is
`cd <coordination_root>/runtime/eve-agent && PATH=<node 24 bin>:$PATH npm ci --no-audit --no-fund`.
`npm ci` rather than `npm install` is deliberate: the committed lockfile is the transitive pin, so a
run installs exactly the resolved set. `install/experiment.py`'s `eve-lockfile-integrity` capability
is a **blocking** probe that reads the four resolved versions out of this file and requires a
non-empty `integrity` for each; a lockfile whose resolved set or integrity fields do not match is a
refusal before the first write, not a degraded warning.

### Invariants And Boundaries

- Generated content, never hand-edited; `eve_runtime/package-lock.json` is the authored source.
- The committed lockfile is the transitive dependency authority; the operator uses `npm ci`.
- `node_modules/` is never committed and never part of the mirror.

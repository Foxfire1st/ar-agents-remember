## Canonical repair-loop contract

This generated carrier follows its canonical role; it adds no separate role or procedural authority. Before escalating, Manager reads its own rulings and the Architect rulings for this master. Manager settles a same-kind occasion under the earlier ruling and names that ruling in its record. Only an uncovered question goes up through the existing route. Beyond-limit rounds, out-of-requirement scope and developer decisions keep their existing escalation owners; this is not a new scope or approval grant.

When the master line moves, Worker runs its supported leaf sync. If no path changed on both sides, Worker reruns focused tests and reports the code and memory pair to Manager; for a changed pair, Manager obtains the existing Curator's refreshed dependent-document read before routine closeout, and uses its closeout preview. No new freeze goes to Reviewer and no round begins. An overlapping path or a failing focused test instead needs the exact repair and one look by the same Reviewer. Native memory conflicts still go to Curator for content and Manager for capture, verification and staging before Worker continues the supported transaction.

# Silent turn-end notification decision

## Governing Overview

[Plugin overview](../overview.md)

## Purpose

Own the pure, host-free decision about what a role agent's ended turn owes: its parent's wake-up line, a message back to the seat itself for a Worker, Reviewer or Curator that stopped without handing off, or nothing to the parent at all for a seat on an ACP connection that ended its turn with a helper-wait declaration — a seat that instead owes the plugin's own progress checks while it waits. The plugin entry feeds host events and supplies the sender; role facts come from the role-start-published record, and the provider verdict that makes a seat an ACP seat comes from the `acp-providers.json` the plugin writes at its start.

## Contract

A seat ends a turn as waiting when its own last assistant message holds a line starting `WAITING FOR SUBAGENTS:` — after leading spaces, Markdown markers and quoting marks, on any line of that message, with those marks also allowed around the keyword. Only a seat whose provider the host's `acp-providers.json` puts on ACP can declare, and no helper call is ever read as a declaration.

A declared end is neither a hand-off nor a silent end. It adds nothing to the silent-end run and takes nothing from it, gives the parent nothing — neither the no-hand-off message nor MIK-R172's line — and, where the same turn also hands off, gives the parent exactly what a hand-off gives. It opens or renews one wait for that seat, recorded with the ordinal of the declaration, and arms one check three minutes after it whatever opened the turn; a turn end without a declaration ends the wait, and so does the seat's archive; a declaring end for a seat the plugin already holds as archived arms nothing for it and ends the wait that seat already holds, with the ended reason `the seat was archived`. The check names the seat's role, agent id and task, asks for each helper with what it does, its status and what came back, and asks the seat to declare again or go on. It passes the same gates as the seat message: never into a running turn, the limit resume built from the check's own text for a limited seat, and a new three-minute arming for a seat in a permission wait or with an unreadable host state; a check this build does not deliver writes its skip with the reason; on the shed branch that skip row is the only row an undelivered check writes — the ordinary wake's `send-skipped`/`over-capacity` row is not written for it, while ordinary wakes keep it.

One recogniser decides which AR tool a `tool_call` row names and reads its answer: the bare name, `<server>.<tool>`, and each Hermes title with or without a preview, with non-AR ACP kinds never matching; the answer comes from Codex's `output` or from Hermes's text in either wrapper after one unescape, and a cut answer is read as far as it shows. The recipient is read from Codex's `input` or from a Hermes answer that names it. A row that shows no recipient still counts as a hand-off where it is one, but never as a return to its parent.

A turn hands off when its own rows hold a `role_message` whose finished answer is not `refused`, `ok: false` or `recipient-busy` (delivered, held and the waiting outcomes all count), or a `task_doc` write that is not `ok: false`. A leaf seat may start no role, so a `role_start` is no hand-off of theirs.

An end is silent only when the turn completed, holds no hand-off, declares no helper wait, and nothing holds it: the seat is not archived, waits for no permission, has no child agent in a turn, and is not answering a waiting sender. The turn's rows are, when the host tags them with the event's turn id, the rows carrying that id; otherwise those after the seat's previous end as this build saw it — its remembered row count and the identity of its last row — falling back to the last `user_message` on the first end seen or when a replaced timeline no longer holds that row. A child is an agent whose `paseo.parent-agent-id` label names the seat, read from the host's agent list; only a listing that ran to exhaustion supplies authoritative host facts, and an incomplete listing leaves the seat alone.

Every silent end waits 60 seconds before anything is sent, the counted parent line included. A turn of the seat that starts inside the wait cancels the send and the end is not counted. At the end of the wait the host state is read again: only a seat out of a turn, unarchived and owing no permission is acted on; otherwise nothing is sent, a row is written, and the end is not counted.

The first two silent ends in a row send the seat one message: a fixed first line of the plugin's own, its role and task, the ended turn's own last line of text shortened to 300 characters, that the turn ended with no hand-off, and an instruction to go on with its stage in this turn or to send what blocks it to its parent with `role_message`; when the turn's rows hold a `delegate_task` call the message adds that a helper's result does not come back as a message here. On a seat whose provider the host puts on ACP that closing instruction is replaced by one sentence naming the declaration among the allowed ways to end a turn — go on with the stage in this turn or send what blocks it to its parent, and, where it waits for helpers, end the turn with a line starting `WAITING FOR SUBAGENTS:` followed by a progress report: each helper, what it does, its status, and what came back — while the fixed first line, the quoted last line and the cap stay as they are. From the third on, every silent end sends the seat nothing and gives its parent MIK-R172's line marked with the count. The count is per seat agent id and returns to zero on a hand-off or on a turn begun by a message the plugin did not send. Only Workers, Reviewers and Curators are sent back; a parent that is in a turn is still told when its turn ends rather than steered into it, unless the product knows its provider keeps its turn under a steer.

**L184 gates, beside the guarantees above.** A seat whose publication shows a running subagent is left alone at its end and gets nothing at the end of its wait, and that end is not counted; when the last running subagent finishes outside a turn the plugin starts the 60 s wait for that left-alone end once and judges archive, permission, turn and subagent again. A seat the limit file names as limited gets no seat message and no marked line: the plugin arms one resume at the reset plus `PROVIDER_LIMIT_RESUME_MS`, re-arms it when the reset moves later, and cancels it when the seat's own turn starts. A parent the limit file names as limited takes no line now; its line is held and flushed once that parent is no longer limited. The limit is read from the file the serving side wrote and from nothing else, so a missing file, an unreadable one, or a report without a limit means no limit, and neither a subagent-holding end nor a limited one counts toward the two; a declared end adds none and takes none away — it is not silent, gets no seat message, and sends its parent nothing unless that same turn handed off. The 60 s wait, the two-send rule, the no-steer rule, the FIFO delivery and the generation guarantees above are unchanged by these gates.

A leaf agent whose recorded parent is archived or missing gives its line to the current Manager of its master; an agent the product's agent list does not hold gives no line and is named in the host log once. The tracker records active turns, permissions, parent links, the provider each agent runs on, the per-seat timeline mark and silent-end run, the open helper-wait declaration of each seat, and the pending wait of each seat. Its historical maps — parent links, the started order, provider history, departed agents, silent runs, seats' epochs and timeline marks — keep capped windows; the active turn and permission sets are live state with no historical cap, and the pending waits are capped fleet-wide at `TURN_ENDED_WAIT_LIMIT`, one wait per seat, an end past the cap shedding its own wake with a skipped row, and a declared seat's three-minute check is one of these waits; the open declarations are held per seat for the silent-limit window and cleared on cleanup. A delivery in flight is not a separate registry: its wait leaves the map before the host await, and a later epoch makes the continuation void. A subject with a direct child in a turn is held, and a line whose parent awaits permission waits; a batch that has just started a turn in the parent leaves the rest owed. Flushes do not overlap, and delivery order is the order the turns ended even across requeues and a Manager rebind.

Every decision row the current generation emits is offered to the plugin's own files through `turn_log.ts`: one JSON row per line in `turn-ends.jsonl` for each message sent, marked line, cancelled wait, skipped send and left-alone end, for each declared wait and each end of one, and for each progress check sent or skipped, with the file turned over at 2 MiB to one retained archive, and a failed write named once in `turn-ends.error.json`. An obsolete intake outcome and a send that spans a generation boundary emit no row, an unmarked ordinary parent line is not a rule row, a sink without `PASEO_HOME` writes nothing, and a failed write is best-effort. `host-activity.json` keeps its bytes.

## Boundaries

The implementation caps a line at `TURN_ENDED_LINE_LIMIT`, the carried last line at `TURN_ENDED_LAST_TEXT_LIMIT`, the self-wake run at `TURN_ENDED_SENT_BACK_LIMIT`, the wait at `TURN_ENDED_WAIT_MS`, the progress check at `SUBAGENT_WAIT_CHECK_MS` and the log at `TURN_END_LOG_LIMIT_BYTES`; the decision does not read roleMessageLimit dynamically. The historical stores keep bounded recent windows and hold no owed line, and an evicted or absent provider reads as unknown, so a lost entry can delay a wake but cannot send into a running turn. The log records the plugin's own decisions and writes; it is not a census of messages the host delivered. The plugin's own test files are source definitions run host-free: a case named there is not a measured runtime witness of a live host delivery. These are in-memory event decisions and host-free composition, not durable message filing, cross-process deduplication, live SDK delivery proof, or a promise about repeated host events. Host wiring is `turn_events.ts`.

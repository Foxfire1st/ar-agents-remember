## Purpose

`route_index_census.py` is the deterministic source-identity boundary for route-index generation.
It validates the requested Git root, freezes exact tracked/untracked repository membership, and
derives path-rule eligibility once for all routes.

## Code Commentary

### Logic

`route_index_source_snapshot()` first proves `git rev-parse --show-toplevel` equals the requested
root. It reads tracked stages through `git ls-files --stage -z`, removes worktree/index deletions
reported by `git diff-files --name-only --diff-filter=D -z`, and retains ordinary executable/file
and symlink modes while excluding directories and gitlinks. It then reads untracked non-ignored
paths through `git ls-files --others --exclude-standard -z` and classifies them with non-following
`lstat`. NUL-delimited records and `surrogateescape` preserve exact path identity.

The resulting `SourceSnapshot` exposes the frozen candidate paths as `repository_paths` and a
second `eligible_paths` tuple filtered through `resolve_storage_for_source`. Route rendering can
therefore distinguish source membership from onboarding eligibility without rerunning Git or
walking the filesystem.

### Conventions

`SourceCandidate` records path, Git/file mode, and tracked/untracked origin. The module returns
immutable tuples in stable path order. Git execution uses the shared selector-scrubbed runner.

### Invariants And Boundaries

- Root validation is authority: a mismatched or non-repository root raises `AuthorityError` before
  a census is trusted.
- After root validation, malformed/non-zero Git results raise `RouteIndexCensusError`; timeout,
  `OSError`, and `lstat` failures preserve their original causes for typed diagnosis.
- Ignored paths and path-rule-excluded generated outputs never enter `eligible_paths`.
- Symlink classification never follows the target, so target appearance/disappearance cannot
  change link identity or force an index rewrite.
- Sparse checkout absence, matched deletions, gitlinks, and non-UTF-8 names have explicit identity
  rules; no permissive fallback walk may replace them.
- These guards protect authority, identity, and convergence. They are required for deterministic
  generated bytes, not speculative defensive scaffolding.

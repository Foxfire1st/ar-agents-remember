## Code Commentary

Selected sprint/master receipts live under the actual task’s notes/reports execution store. New requests use the canonical Investigator directory; exact reads also inspect the one earlier role spelling and the earlier Projects singleton address without moving stored files. A repeated UUID with more than one recorded address refuses rather than selecting a path.

The display retains the newest fifty requests and an omitted count. Capacity and role-address ambiguity use the complete not-closed set independently of that display. Under one selection lock, starts and new turns addressed to a completed recipient refresh the complete open set and refuse at eight before native send or resume. A running recipient’s steering and exact-request replay reuse the existing slot; delivered new-turn state is refreshed before releasing the lock. Projects retains its separate existing listing/ownership behavior. No new queue, retention policy or copied task hierarchy belongs here.

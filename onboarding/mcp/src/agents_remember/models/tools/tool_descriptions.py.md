## Purpose

States the character ceilings and the transition ownership used by the registered-tool description checks. It is declaration data, not a runtime answer shaper or a source of permission to call a tool.

## Code Commentary

A normal registered-tool description is bounded to 600 characters and an argument's schema description to 120 characters. The calling agent's longer explanation belongs in an openable skill or reference, rather than in an answer example, refusal catalogue or argument-description overflow.

Description ownership and answer ownership are related but distinct. The current map has no L109 entries: context_packet, read_ar_files, knowledge_read and knowledge_diff have final candidate answer rows and ordinary description bounds; resolve_context is removed, not retained as an interim reader. The interim-owner map records which later reader, memory or task/landing leaf rewrites a retained tool; checks use the answer table's interim marking when available. A finalized answer row subjects its description to the ordinary bound without changing the test. The retained `dispatch_agent` description has its own pinned length until its replacement and removal land together; this is a transition preservation rule, not an additional general exception table.

Do not turn the declaration's transition map into a current roster, infer that a listed tool is registered, or claim that every description in an arbitrary build already meets the ordinary ceiling. The roster, actual registration and table-derived test decide those facts.

# Observer — Native Task Facts, Host Activity And Workspace Evidence

## Governing Overview

[mcp overview](../../../../overview.md)

## Purpose

`observer/` joins authored task facts, exact worktree identity and the host publication into one native task model, and interprets supplied structural/analytical evidence for the dashboard. It owns native TaskState/TaskEntry schemas and their producer, the host publication model, workspace Event River envelope/storage/retention, content-free completed-call events, provider/process/attention/graph builders and supporting DTOs. It does not restore an ambient agent lifecycle, a session State/Phase model, served-onboarding deduplication, lifecycle heartbeat/TTL inference or per-lifecycle log reduction.

File-surface acquisition, shared task/contract inputs, host-to-task binding, landing observation, drift pruning and atomic projection publication remain serving responsibilities. Contract/task writers own canonical task stages; the host owns observed agent activity. Read/projection code neither writes task stages nor manufactures a second browser/session state authority.

## Hot Path Summary

1. task_entries.py is the one task/state/membership join; projection.py owns native TaskState, TaskEntry, optional structured list disagreements and workspace counts. Documented-subTask master precedence and genuinely absent-master list fallback are resolved here, not in the browser. Their present contrary/unresolvable masters stay explicit and unbound, and each distinct disagreement is reported once per declaring master. Other listed kinds use list placement under identity/cycle guards; this path does not reject their kind or validate their own master.
2. host_activity.py validates published host states and event timestamps; serving/projections/host_activity.py owns publication acquisition and caller/parent task binding.
3. reducer.project_workspace composes supplied facts, passes native tasks/counts through and returns only unbound worktrees in the separate enclosure collection.
4. tool_events.py writes selected finalized-call facts to the bounded workspace river; store.py and event_retention.py own its lock, byte admission and cursor-safe retained tail.
5. reducer_impl builds provider/drift/setup/start attention and engine/process evidence. projection_graph.py retains supplied graph display semantics, not execution admission.
6. Reader summaries and selected full bodies remain separate; task stage/activity and actual eventAt are not recomputed from browser time or old lifecycle logs.

## Construction And Ownership

### L184 — the limit read and the running-subagent fields

A new read-side module, `observer/provider_limits.py`, reads the product's one limit file at observer, so the status function needs no upward import to learn a seat's limit. The host-activity model in this route also admits the running-subagent fields: a supplied subagent count and its since-time travel with the agent facts, which is what lets a seat whose only work is a running subagent read as working rather than idle.

### One native task model

TaskState separates planned/started/aborted/completed stage from optional works/paused/unknown activity and eventAt. A non-started canonical stage wins over host activity. An unavailable/incomplete host observation cannot prove paused; a complete known host may establish works from in-turn/permission agents, and also from an agent whose state is not ended while its running subagent count is above zero, whose contributing time is that subagent activity's; otherwise paused. A started task with none of its agents working and at least one of them limited carries the served limited word while every count and the grouping keep saying paused. The timestamp comes from working contributors when present, otherwise the observed agents, not a generated heartbeat or elapsed-age counter.

The task-entry producer keeps repository-qualified document identity, optional document references, ordered parent/children links, authoritative step counts, summaries and exact contract bindings together. A declared file-less child can be a native entry without a document reference; consumers must not invent a document jump. Declared-parent checks and the single-parent acyclic membership guard prevent another client-side series/lifecycle hierarchy. The retained explicit orchestrates relation resolves only a unique same-repository commanded master; this is a named task-domain compatibility relation, not a broad title/filename guess.

HostActivityPublication carries bootId, complete, the agent map and ignoredEvents. PublishedAgentActivity admits in-turn, permission, idle and ended; supplied eventAt must include a timezone. The pure projection receives a HostActivitySnapshot with known/agents/ignored_agents. Publication completeness, caller/task binding and ignored-agent accounting are distinct facts; the ignoredEvents and ignored_agents cells are not interchangeable counters.

### Workspace Event River

The event envelope remains ar-observer-event/v1 with explicit trust and actor provenance. It is persisted event data, not an MCP response or task-state authority. EventStore now writes workspace/events.jsonl only. There is no per-lifecycle append path, current ambient owner, heartbeat.json update, lifecycle replay state machine or served-file ledger in this account.

Workspace append and compaction share the cross-process exclusive events.lock. The declared default ceiling is 16 MiB with an 8 MiB trim target; a row that still cannot fit is refused. Age compaction and the one-hour fresh-connect retained window are separate from the append-size check. Physical compaction increments the virtual base offset; river replacement and cursor-sidecar publication remain separate writes, preserving the historical N2 crash-window limit rather than asserting a transaction that does not exist.

The noncreating workspace_river_read opens an existing lock read-only and reports whether a shared lock was obtained. A failed/missing lock is not evidence of a coherent river/cursor pair. EventStore.read tolerates malformed event rows; that local read behavior is not a blanket promise that every reader contains every I/O failure.

The current ToolEventWriter retains its caller snapshot, lock and process-local dropped-event count. Its selected facts exclude argument/answer/message bodies and caller-supplied paths; overlong strings are omitted. Publication failure or an unadmitted row increments dropped; success resets it, and a restart can lose the count. Its bounded lock wait/containment belongs to this writer, not to every EventStore caller. Compatibility rendering or synthetic fixtures for read.packet do not establish a current emitter or restore ambient tool attribution.

### Retained provider, process, graph and serving boundaries

Engine nodes join enclosure facts, status/guidance, isolated providers, and setup by worktree-group basename. Disposed completed/abandoned cleanup facts are filtered; cleanup-pending remains visible. Pre-contract starts receive synthetic nodes unless a contract for that group already anchors them; stale-base and source-lineage blocks map to preflight. Code/memory references, boot roles, edges, missing facts, and observed/derived/planned/missing distinctions preserve evidence honesty. External-memory lanes exist only for external-memory contracts. Landing refs, integration strategy, PR milestone time, carryover completion time, source lineage, and next-action guidance are display evidence supplied by their owners.

Provider builders expand explicit CGC watcher and target-repository evidence into repository-scoped nodes, preserve aggregate nodes when such evidence is absent, and distinguish configured-only worktree nodes from runtime observations. One provider runtime can cover several addressable memory targets. Missing expected boot roles remain distinguishable from observed or failed roles rather than fabricated healthy state.

The graph builder accepts protocols/plain facts without importing the tasks package. Leaf title lookup uses `(owning TaskDocumentRef, leaf id)`, so equal local ids under different masters remain distinct. Serving supplies walked edges and waves; observer orders views by supplied waves and declaration order and preserves predecessor reasons/judgment ids. Landed requires completed work; resolved also permits abandonment. Frontier selection checks landed, then abandonment, then unresolved predecessors, then in-flight, then ready. A segment can display abandonment if any named leaf is abandoned while remaining unresolved until all named leaf statuses are resolved. Missing master facts never establish landed or in-flight, although a node with no unresolved predecessor can display ready. These are display predicates, not execution admission.

Drift is read from persisted snapshots, not reclassified by the fold. Valid snapshots remain for configured repository names or contract-backed existing code worktrees; valid orphans are physically removed and malformed snapshots are skipped. Verification-age sidecar inventories, histogram and stalest leaderboard are retired. Persisted converted drift snapshots and explicit code-anchor currentness are distinct retained observations.

## Invariants And Boundaries

The fold consumes already-read inputs and performs no filesystem or Git work. File acquisition and publication belong to serving. Persisted event provenance must not turn declared claims into observations; inference is marked, while contract-derived abandonment is structural evidence rather than a foreign event. Terminal vocabulary identifies end outcomes, but projected terminality also arises through valid corrections, dormant-fleeting inference, and abandoned anchors. It is therefore too strong to say every projected terminal state is reachable only through `lifecycle.ended`.

Raw retention distinguishes activity from liveness. Unprotected lifecycle logs become dormant after more than one hour without real non-heartbeat activity, and pruning removes the entire directory, including heartbeat and served-record sidecars. The pruning function considers directories with an event file; this proposal makes no claim of universal orphan-directory reclamation. Fresh connects replay a recent one-hour window and start dormant lifecycle logs at EOF. Workspace age retention and byte admission are separate boundaries; virtual offsets carry reclaimed byte counts. Compaction writes the event file and cursor sidecar separately, so the inherited crash-ordering limit remains material.

Durable series protection supersedes inactivity pruning for enclosure ids grouped by repository and task name. Every represented leaf of a nonretired group is protected. Retirement requires all represented leaves to have completed/abandoned cleanup and more than one week since the latest readable contract mtime; if no finalized timestamp can be read, an all-archived group retires without an extended grace. Enclosures without task names and standalone/fleeting logs are outside this protection. Retention protection does not mean full history is replayed on a fresh event connection.

Durable enclosure state also supplies runtime admission when a lifecycle log is missing. A present terminal log demotes both admission sets. Provider admission additionally requires a provider-relevant phase, nonarchived cleanup, and incomplete closeout/integration; engine admission is broader and retains nonterminal close/integration work. This keeps missing prunable evidence from automatically removing a live durable enclosure. Topology receives the same sorted engine admission set. Historical enclosure collections and current lifecycle reconciliation should not be conflated into a promise that every historical lifecycle is always served.

Attention is derived, ranked by severity then descending wait then stable id. It includes open gates, bare blocks, provider failures, actionable drift, failed/stale setup, blocked starts, quiet sessions, dormant fleeting sessions, and a single informational awaiting-developer item. A blocked lifecycle with an attached open gate does not also produce the bare-block item. Synthesized paused persistent rows with no event timestamp do not raise a quiet-session alarm. Dismissal matches lifecycle and optional kind, and holds until a newer triggering signal; a missing signal remains suppressed under that predicate. Only actionable drift is targetless dismissible attention. Serving prunes acknowledgements against projected nonterminal lifecycle ids. Gate-source cancellation/deletion, rather than generic acknowledgement history, governs gate-open attention.

Rendering tolerates evidence failures only at named boundaries. Gate reading uses `projected_current` and expectation reading uses `pending_for_projection`, avoiding whole-file silence from catching a strict parse failure as `ValueError`. Gate retention is applied in memory and no gate compaction is performed by that reader; with no supplied time, that retention filter is not requested. The inherited authority policy requires strict reads for authority-bearing rewrites and keeps rendering tolerance separate. This does not establish that every projection reader is nonmutating: present serving pickup reading calls inbox compaction, projection publication prunes dismissal records, lifecycle refresh prunes directories, and drift refresh removes orphan snapshots. The old blanket prohibition remains useful gate-log intent but is inaccurate as a description of all serving orchestration.

Pickup reading retains pending rows and carries routing, owner, retry/escalation, artifact, and delivery facts. Its strict inbox calls contain named I/O/validation failures at whole-call boundaries, not the per-row tolerance of gates/expectations. Durable-store errors are documented to propagate. Expectation rows are an owner-visible deadline surface, not correctness predicates driven by projected data; an invalid deadline string is displayed as not overdue by the local reader. The inherited five-minute pickup/check-chat and 24-hour interaction policy must remain distinguished from durable tasks, contracts, and ledgers, which are not interaction-retention targets.

Best-effort ledger enrichment explicitly catches both `OSError` and `subprocess.SubprocessError`, including the shared Git runner's timeout, and can retain hash-only rows. Local engine status and landing merge have their own containment. These concrete predicates support degradation claims at those boundaries, not an unqualified guarantee that every reader can never raise.

Drift is read from persisted snapshots, not reclassified by the fold. Valid snapshots remain for configured repository names or contract-backed existing code worktrees; valid orphans are physically removed and malformed snapshots are skipped. Verification-age sidecar inventories, histogram and stalest leaderboard are retired. Persisted drift snapshots and explicit code-anchor currentness remain distinct supported observations.

Landing refresh is serving-owned, bounded, exact-contract observation. Completed arcs can use a persisted final observation only while cleanup remains completed and its provenance does not predate the contract write. Freezing requires a nonempty probe whose every row is observed; frozen rows are restricted to reducer-known keys. Open/reopened arcs can return to live observation. A completed eligible successful-landing arc without a trusted final gets one finishing opportunity per exact contract key in this refresher lifetime, including at startup, with at most four completed admissions per sweep. An attempt that returns missing-fact placeholders after failure also spends that opportunity; later final-file loss alone does not rearm it. Reopen clears the key's spent marker. Untrusted finals remain explicitly missing until a permitted observation establishes valid history. An observation returning no applicable landing rows does not mark that key finished. Failed cycles are contained for the next cadence and cancellation propagates. PR milestone time and carryover completion remain display-only facts. Observation does not authorize landing.

### Task readers and attention

Always-on native entries/summaries do not carry the complete selected reader body. Current identity, stage/activity, counts, step/review facts and bodyRevision remain authoritative; on-demand bodies contribute long reader content and admitted matching-revision expansions. Canonical enumeration, graph-named masters and declared owner/child reads have their own actual scopes; this is not an unconditional promise of zero directory I/O or universal body-byte parity. Source-defined truncation and step-preview bounds do not become fresh execution or payload-budget acceptance.

Attention now derives provider failure, actionable drift, failed/stale setup and blocked-start items together with five native kinds — an unanswered permission prompt, a held role message, a started task idle past 900 seconds with no bound agent working, and terminal landed and abandoned notices — ordered by severity, descending wait and stable id. The three live causes clear only when their native cause ends and cannot be acknowledged; the two notices are acknowledged once per occurrence. `native_attention.py` declares the fact shapes and their named bounds, `reducer_impl/_attention_native.py` holds one builder per kind, and `serving/projections/native_attention.py` is the intake that reads the product's own files and resolves nothing from an incomplete read. It does not reconstruct session blocked/awaiting-developer/quiet/fleeting attention. The fold suppresses the reconciled source-owned dismissal map; provider/setup/start recovery belongs to their native observations, while drift matches complete actionable fingerprints and retains admitted first-read acknowledgements when a fingerprint is missing. Missing data or elapsed age is not invented recovery.

> ## Construction And Ownership
>
> Task and series-child projection nodes may show typed external directGrant giver/time evidence. The schema neither reads nor writes grants and is not routing authority; authored TaskDocument remains unchanged.
>
> `events.py` defines `ar-observer-event/v1`, a closed persisted record with camelCase wire keys, explicit trust (`declared`, `observed`, `inferred`, `approved`) and actor (`model`, `system`, `developer`). Developer delivery channel is separate event data. The envelope is not an MCP response model and carries no response token fields. Writers serialize with aliases and omitted nulls; readers validate records. `ulid.py` supplies local sortable identifiers without coordinated minting. Replay relies on append-ordered, nonempty lifecycle inputs and a self-contained starting record; the reducer does not turn arbitrary input into an independently certified audit history.
>
> `store.py` resolves lifecycle/workspace paths, appends records, coalesces heartbeats, and provides tolerant event parsing. Its lifecycle single-writer rule is an ownership assumption: the live adopted session owns its lifecycle file, and the ambient lock coordinates its request and heartbeat threads. It is not a cross-process lifecycle lease enforced by `EventStore.append`. Dead-lifecycle cleanup projects or removes evidence rather than appending a foreign terminal event. Workspace storage has multiple process writers and therefore uses its own lock. The noncreating shared-lock read helper reports whether a lock was obtained; readers using that pairing must not treat a failed lock as a coherent river/base pair.
>
> `ambient.py` owns guarded start, block, blocked-only resume, turn-end notification and its separate resume path, end, phase, switch, promote, attach, tool/read attribution, heartbeat, and opportunistic fleeting cleanup. Starting while another lifecycle is current refuses. `await_developer(summary=...)` requires running, records a nonterminal notification without waiting or opening a gate, and `resume_from_await` accepts only that state; the ordinary `resume` retains its blocked-only guard. `end` refuses unknown outcomes before emitting and clearing the ambient. Attach adopts the resolved identity for subsequent attribution; it does not replay the entire state history, and a same-id attach is a no-op.
>
> Leaving persistent work pauses it. Leaving fleeting work requires an explicit save/discard decision: no decision raises `SaveGateRequired`; save promotes to a scope-tagged landing zone and pauses; discard deliberately writes abandonment. There is no automatic-save default. `save_gate.py` validates that vocabulary and computes a single-repo scope, `0_unscoped`, or explicit `1_cross-repo`; landing-zone promotion records scope rather than constructing a worktree. The literal abandonment chosen by discard is distinct from the tolerant read-side default for malformed end outcomes.
>
> `lifecycle_state.py` reads and checks the state/phase vocabulary now declared in `models/lifecycles/responses.py`. Live states are running, paused, blocked, and awaiting-developer; terminal states are the end outcomes completed and abandoned. The partition check refuses overlap, unfiled states, orphaned members, and invalid vocabulary members. Read-side end coercion defaults an unknown or absent outcome to abandoned; ambient writes refuse such input. `timeutil.py` owns the shared 15-second heartbeat, 180-second quiet threshold, and 3600-second fleeting TTL; stamp aging comes from the lower shared control-plane primitive. Provider setup timing remains a separate provider concern.
>
> The heartbeat wait uses short sleeps against a monotonic deadline and rechecks the stop flag. A beat exits when no lifecycle is current or it is terminal. After more than ten minutes without real activity it stops emitting, while the loop remains able to emit again after real activity. Heartbeats do not reset the real-activity clock. Ambient's opportunistic sweep separately deletes old, never-promoted fleeting directories, excludes the current lifecycle, and never writes a non-owner terminal event.
>
> `served_store.py` maintains a durable served-key record and a separately locked read-through set keyed by kind/path/content hash. This prevents repeated delivery of the same onboarding piece within an adopted lifecycle. Recording advances the in-memory set even when disk persistence fails. Reset deliberately removes both current cache and durable served log to permit redelivery; forget releases memory while preserving history when a lifecycle ends or is left. Neither operation calls back into ambient, preserving the documented lock ordering.
>
> `tool_events.py` constructs content-free workspace `tool.completed` facts from finalized answers and a caller snapshot: tool, result/refusal/state, delivered token count, caller identity/task, and selected target role. It excludes argument values, answer/message text, and caller-given paths; strings exceeding 120 characters are omitted. The writer retains a caller snapshot and a dropped-event counter, with no separate durable lost-event ledger. A restart can lose the count; successful publication resets it. The module documents coexistence with legacy ambient tool emission, but whole-call deduplication and server-start wiring remain outside the locally examined builder/writer.
>
> `projection.py`, `projection_closeout.py`, and `projection_graph.py` own served schemas, including version-2 workspace state, lifecycle/enclosure/provider nodes, task/series/attention/process data, operation DTO attachment, closeout queues, discarded-task proof views, and render-ready sprint graphs. These records are distinct from tool-response ownership. Operation DTOs come from the lifecycle model owner; the present public envelope includes exact candidate/plan identity digests, generation/revisions, component bindings, and public approval/worker observations. Its model refuses incoherent compositions and prevents unreadable/incoherent observations from advertising the forbidden authority described by that model. Private operation keys and worker PIDs are not fields of this top-level projection model.
>
> `reducer.py` remains a facade and lifecycle/workspace fold, with attention, metrics, process composition, and input bundles in `reducer_impl/`. `WorkspaceStructure` supplies enclosures, providers, and active worktree groups; `AnalyticalInputs` supplies defaulted analytical and supporting inputs, including closeout queues. New inputs belong in the appropriate bundle rather than a growing keyword list. Omitting analytical inputs uses empty defaults, but structural evidence can still produce derived attention or lifecycle state; it is not a universal promise of empty analytics.
>
> The reducer folds phase, block, notification, resume, pause, promotion, and end events; applies valid append-only state corrections at the corrected event's position; stamps written state changes; and computes quiet/dormant inference. Running becomes inferred paused after the quiet threshold; nonterminal fleeting state becomes inferred abandoned after the TTL. Unknown event kinds still contribute last-event timing. Notification summary rides the ask carrier and resume clears it. Live-state metrics derive bucket names from the checked live vocabulary, preserve hyphen-tail case, reject naming collisions, and populate explicitly declared closed `Metrics` fields. An undeclared computed bucket is a validation failure; there is no present bidirectional test assertion established by this proposal.
>
> Workspace assembly reconciles older persistent event-backed rows against current enclosure ownership, terminalizes nonterminal persistent rows anchored to abandoned contracts, synthesizes paused persistent rows for eligible missing-log enclosures, attaches latest open gates, and composes attention and engine nodes. Fleeting rows and fresh nonterminal, noninferred materialization windows are exceptions to missing-anchor removal. Reowned anchors reject an old lifecycle when a different owner is recorded; an enclosure with an empty lifecycle id does not impose that equality check. Missing-log synthesis excludes abandoned and reopened cleanup states; its local predicate does not inspect physical worktree existence or exclude completed cleanup by itself. Serving provides the enclosure universe and existence fields, so this local observation must not be inflated into a whole-call-path absence claim.
>

Disposed completed/abandoned cleanup facts are filtered; cleanup-pending remains visible. > ## Invariants And Boundaries
>
> The fold consumes already-read inputs and performs no filesystem or Git work. File acquisition and publication belong to serving. Persisted event provenance must not turn declared claims into observations; inference is marked, while contract-derived abandonment is structural evidence rather than a foreign event. Terminal vocabulary identifies end outcomes, but projected terminality also arises through valid corrections, dormant-fleeting inference, and abandoned anchors. It is therefore too strong to say every projected terminal state is reachable only through `lifecycle.ended`.
>
> Raw retention distinguishes activity from liveness. Unprotected lifecycle logs become dormant after more than one hour without real non-heartbeat activity, and pruning removes the entire directory, including heartbeat and served-record sidecars. The pruning function considers directories with an event file; this proposal makes no claim of universal orphan-directory reclamation. Fresh connects replay a recent one-hour window and start dormant lifecycle logs at EOF. Workspace age retention and byte admission are separate boundaries; virtual offsets carry reclaimed byte counts. Compaction writes the event file and cursor sidecar separately, so the inherited crash-ordering limit remains material.
>
> Durable series protection supersedes inactivity pruning for enclosure ids grouped by repository and task name. Every represented leaf of a nonretired group is protected. Retirement requires all represented leaves to have completed/abandoned cleanup and more than one week since the latest readable contract mtime; if no finalized timestamp can be read, an all-archived group retires without an extended grace. Enclosures without task names and standalone/fleeting logs are outside this protection. Retention protection does not mean full history is replayed on a fresh event connection.
>
> Durable enclosure state also supplies runtime admission when a lifecycle log is missing. A present terminal log demotes both admission sets. Provider admission additionally requires a provider-relevant phase, nonarchived cleanup, and incomplete closeout/integration; engine admission is broader and retains nonterminal close/integration work. This keeps missing prunable evidence from automatically removing a live durable enclosure. Topology receives the same sorted engine admission set. Historical enclosure collections and current lifecycle reconciliation should not be conflated into a promise that every historical lifecycle is always served.
>
> Attention is derived, ranked by severity then descending wait then stable id. It includes open gates, bare blocks, provider failures, actionable drift, failed/stale setup, blocked starts, quiet sessions, dormant fleeting sessions, and a single informational awaiting-developer item. A blocked lifecycle with an attached open gate does not also produce the bare-block item. Synthesized paused persistent rows with no event timestamp do not raise a quiet-session alarm. Dismissal matches lifecycle and optional kind, and holds until a newer triggering signal; a missing signal remains suppressed under that predicate. Only actionable drift is targetless dismissible attention. Serving prunes acknowledgements against projected nonterminal lifecycle ids. Gate-source cancellation/deletion, rather than generic acknowledgement history, governs gate-open attention.
>
> Rendering tolerates evidence failures only at named boundaries. Gate reading uses `projected_current` and expectation reading uses `pending_for_projection`, avoiding whole-file silence from catching a strict parse failure as `ValueError`. Gate retention is applied in memory and no gate compaction is performed by that reader; with no supplied time, that retention filter is not requested. The inherited authority policy requires strict reads for authority-bearing rewrites and keeps rendering tolerance separate. This does not establish that every projection reader is nonmutating: present serving pickup reading calls inbox compaction, projection publication prunes dismissal records, lifecycle refresh prunes directories, and drift refresh removes orphan snapshots. The old blanket prohibition remains useful gate-log intent but is inaccurate as a description of all serving orchestration.
>
> Pickup reading retains pending rows and carries routing, owner, retry/escalation, artifact, and delivery facts. Its strict inbox calls contain named I/O/validation failures at whole-call boundaries, not the per-row tolerance of gates/expectations. Durable-store errors are documented to propagate. Expectation rows are an owner-visible deadline surface, not correctness predicates driven by projected data; an invalid deadline string is displayed as not overdue by the local reader. The inherited five-minute pickup/check-chat and 24-hour interaction policy must remain distinguished from durable tasks, contracts, and ledgers, which are not interaction-retention targets.
>
> Best-effort ledger enrichment explicitly catches both `OSError` and `subprocess.SubprocessError`, including the shared Git runner's timeout, and can retain hash-only rows. Local engine status and landing merge have their own containment. These concrete predicates support degradation claims at those boundaries, not an unqualified guarantee that every reader can never raise.
>
> Drift is read from persisted snapshots, not reclassified by the fold. Valid snapshots remain for configured repository names or contract-backed existing code worktrees; valid orphans are physically removed and malformed snapshots are skipped. Large sidecar inventories become a histogram and bounded stalest list rather than full served inventories.
>
> Landing refresh is serving-owned, bounded, exact-contract observation. Completed arcs can use a persisted final observation only while cleanup remains completed and its provenance does not predate the contract write. Freezing requires a nonempty probe whose every row is observed; frozen rows are restricted to reducer-known keys. Open/reopened arcs can return to live observation. A completed eligible successful-landing arc without a trusted final gets one finishing opportunity per exact contract key in this refresher lifetime, including at startup, with at most four completed admissions per sweep. An attempt that returns missing-fact placeholders after failure also spends that opportunity; later final-file loss alone does not rearm it. Reopen clears the key's spent marker. Untrusted finals remain explicitly missing until a permitted observation establishes valid history. An observation returning no applicable landing rows does not mark that key finished. Failed cycles are contained for the next cadence and cancellation propagates. PR milestone time and carryover completion remain display-only facts. Observation does not authorize landing.
>
> Serving delta removes explicitly declared volatile ages from stable comparisons to avoid heartbeat-only content churn. The inherited policy requires new `*Seconds` fields to declare volatile or content status; its historical reflection-test witness is not fresh verification here.

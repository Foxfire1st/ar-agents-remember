# .gitignore

## Governing Overview

[repository overview](overview.md)

## Purpose

Keeps machine-local environments, caches, generated bundles and task scratch out of Git candidate
content. The frozen MCP application lock is explicitly retained even though ordinary uv locks
are ignored.

## Code Commentary

The `.venv` and `.venv/` patterns exclude the task code worktree's `mcp/.venv`; `node_modules/`
also excludes Node dependency trees. Git-based working-path enumeration uses the ignore rules
when adding untracked files. These patterns do not build an environment or prove a transaction
ran. Candidate commands still use the worktree-owned environment prescribed by tool notes;
installed product tools and memory operations remain on the landed build.

The file also excludes Python bytecode/tool caches, generated cockpit artifacts, local
settings and task scratch. The `!mcp/uv.lock` exception keeps the application's frozen dependency
input versioned. No ignore pattern grants permission to remove another worktree or a shared cache.

## Evidence

- The repository ignore rules exclude Node modules and local virtual environments while retaining the MCP lock. [1]

- The accounting regression requires a real venv and checks product enumeration; it does not execute cleanup. [2]
